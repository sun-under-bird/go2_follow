排除 `.git`、构建、安装和日志目录后，文件内容比较结果：53 个相同、25 个修改、2 个新增、0 个删除。新增文件是 OrbitUwbOnce.action 及其调用说明。

## 结论与选择建议

**B 的变化集中在 Lite3 平台适配、部署接口、记录工具和新增 UWB 单次环绕动作。普通跟随避障算法没有得到实质改进。**

因此，换成 B 不能解决绕过障碍后追赶加速、低速不平滑、长横障中途原地转的问题。此前定位的最终命令与预测不一致、暖启动候选漏用当前速度限制，也都仍然存在。

B 新增行为节点代码另有直接可见的语法断裂：构造函数残留无效表达式，参数校验中的初始化列表没有结束。它们阻碍从这份源码构建行为节点；这是静态阅读发现，不是编译日志结论。影响包含 FOLLOW、ROAM 和 ORBIT 的统一行为节点，不仅影响环绕功能。独立 local_follow.launch.py 不依赖这个行为节点，但其绕障算法仍有共同问题。

建议按实际部署确定唯一主工作区，在同一份共享控制核心里解决问题。可以保留 B 的记录脚本、诊断参数化和坐标系参数传递；不要因为新增环绕接口而将 B 当成已修复长障碍绕行的版本。若 robot_ws 是实际维护的主工作区，就直接修复其中的 go2_follow_ws，避免持续维护两份分叉实现。

## 2. B 中值得保留的改进

### 记录脚本修复了里程计话题，并允许参数覆盖

A 的脚本硬编码 `/odom_leg`。B 的 [record_follow_test.sh:15](<C:/Users/chy/Documents/ChatGPT/go2_slam 2/robot_ws/go2_follow_ws/scripts/record_follow_test.sh:15>) 默认使用 `/leg_odom2`，增加 `--odom-topic` 和 `--cmd-vel-topic`，记录清单使用这些变量。

这修复了之前指出的记录缺项，利于分析实际速度、里程计补偿和制动过程。它改善诊断能力，不直接改变避障行为。

### 补传 odom_frame，诊断标识可以配置

[local_follow.launch.py:152](<C:/Users/chy/Documents/ChatGPT/go2_slam 2/robot_ws/go2_follow_ws/src/go2_uwb_local_follow/launch/local_follow.launch.py:152>) 现在向规划器显式传递 odom_frame；独立规划器 launch 也做了同样处理。自定义里程计坐标系时，这可以减少地图与规划器参数不一致。

hardware_id/planner_hardware_id 参数贯通节点与 launch，行为节点按配置筛选规划器诊断。不再依赖固定的 Go2 标识，这是部署适配改进。

### 平台定位变得明确，但仍需与真实底盘一致

B README 明确写 DEEP Robotics Lite3，包描述、默认诊断标识、尺寸和最小速度说明也对应 Lite3；包名及 `/go2/...` 接口是为兼容保留。

你此前说明底盘是 Go2，因此不能凭包名认定参数适配正确。修改 hardware_id 只会改变诊断标签，不能改变真实足迹、执行死区、制动能力或桥接层控制语义。A 的部分配置也已经含 Lite3 假设，两个目录都需要核对真实底盘参数。

B 增加 `/go2/orbit_uwb_once`：接近目标半径后，沿以 UWB 目标为中心的圆周生成一个前置虚拟点，再复用原跟随核心与 MPPI；默认半径 1 米、环绕阶段名义线速度上限 0.35 m/s。

普通 FOLLOW 仍走 [computeFollowNominal:1225](<C:/Users/chy/Documents/ChatGPT/go2_slam 2/robot_ws/go2_follow_ws/src/go2_uwb_behavior/src/uwb_behavior_controller_node.cpp:1225>)，没有切换到局部绕行路径。ORBIT 的 [虚拟目标生成:1163](<C:/Users/chy/Documents/ChatGPT/go2_slam 2/robot_ws/go2_follow_ws/src/go2_uwb_behavior/src/uwb_behavior_controller_node.cpp:1163>) 则按目标圆周几何计算点，没有搜索障碍端点或生成障碍感知的引导路线。

因此，此动作增加了“围绕目标运动”的任务类型，不能据此推断它解决了普通跟随穿过长横障的问题，也没有给普通 FOLLOW 增加 0.35 m/s 的绕障限速。

## 4. B 新增行为代码中的明确缺陷

### P1：构造函数残留不完整表达式

[uwb_behavior_controller_node.cpp:195](<C:/Users/chy/Documents/ChatGPT/go2_slam 2/robot_ws/go2_follow_ws/src/go2_uwb_behavior/src/uwb_behavior_controller_node.cpp:195>) 在完整的 orbit_action_server_ 创建语句后，残留 this 和多段没有实际回调的 std::bind，最后还有多余右括号。第 195–201 行不构成合法的这段 C++ 代码。

应查清残留来源，删除无效片段并确认三个 Action 的注册各自完整。单纯调整 launch 或 YAML 无法处理这个问题。

### P1：参数校验初始化列表没有结束

同文件 [第 491 行](<C:/Users/chy/Documents/ChatGPT/go2_slam 2/robot_ws/go2_follow_ws/src/go2_uwb_behavior/src/uwb_behavior_controller_node.cpp:491>) 开始 required_strings 初始化，第 495 行后缺少 `};`，第 496 行直接进入 if。

这同样是源码语法错误，不依赖 ROS 环境即可定位。它阻碍整个行为节点构建。没有据此认定其他代码全部正确；本次没有构建验证。

### P2：环绕反馈函数存在，但没有被调用

同文件 [controlTick:1002](<C:/Users/chy/Documents/ChatGPT/go2_slam 2/robot_ws/go2_follow_ws/src/go2_uwb_behavior/src/uwb_behavior_controller_node.cpp:1002>) 只调用 publishFollowFeedback 和 publishRoamFeedback。[publishOrbitFeedback:2084](<C:/Users/chy/Documents/ChatGPT/go2_slam 2/robot_ws/go2_follow_ws/src/go2_uwb_behavior/src/uwb_behavior_controller_node.cpp:2084>) 只有定义，没有调用点。

即使先修复上述语法错误，环绕 Action 也不会按文档每 0.2 秒返回阶段、角度和距离反馈。应将反馈函数接入控制周期，并覆盖启动、运行、暂停和停止阶段。

### 尚需明确：移动目标下的完成一圈语义

同文件第 1148–1157、1187–1191 行，用机器人相对实时滤波 UWB 中心的极角累计环绕进度。机身原地转向本身不计入进度，这是合理的；但 UWB 中心运动也会改变这个极角。

因此，若目标走动，累计 2π 不严格等价于机器人沿固定圆周走了一圈。后续若实际使用 ORBIT，应明确要求目标静止，或定义对移动目标的相对环绕完成条件，并结合机器人位移、半径误差和中心变化进行判定。这是功能语义限制，不是本次普通 FOLLOW 故障的原因。
