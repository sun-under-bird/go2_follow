# 自然跟随行为与控制设计

日期：2026-09-27。本设计依据本次讨论的目标及当前源码，尚未实施或实机验证。本次不修改控制代码、不编译 ROS2。

## 已确认的产品目标

用户允许盲角减速、短暂停顿、信息不足时拉大距离或停止；希望机器狗的跟随过程自然，并能安全、平滑地避障。

本设计将“像真狗”落实为可观察的行为：跟随节奏随人变化，绕行提前而连贯，选择绕障侧后不反复犹豫，绕过障碍后缓慢接回，不因追赶距离增大突然加速。固定前视相机的朝向与机身绑定，不能独立转头观察；腿部步态由实际底盘控制模式决定。这些硬件边界仍然存在。

优先级为：可执行安全约束 > 运动连续性与适当净空 > 跟随距离误差。接受短时掉队，不为补距离突破前两项约束。

## 1. 场景行为规格

| 场景 | 期望动作 | 验收重点 |
| --- | --- | --- |
| 人匀速直行 | 逐步匹配人的速度，保持一个舒适距离区间 | 不形成周期性追赶、停住、再追赶 |
| 人起步 | 在目标运动得到可信确认后平顺起步 | 无由测量抖动触发的反复迈步 |
| 人减速或停止 | 结合速度趋势和剩余间隔提前减速 | 不到距离阈值才突停，不贴近人体 |
| 人小幅横移 | 路线轻缓调整 | 不跟随每次 UWB 角度抖动摆头 |
| 可见障碍 | 在仍有选择空间时开始绕行，保持适当净空 | 不贴障后急转，不左右反复换边 |
| 长横障 | 维持绕障侧和中间目标，逐段观察端点 | 不因人与机身夹角增大中途切原地对准 |
| 连续两个障碍 | 保持低速，验证接回通道后再恢复跟随 | 第一障碍离开正前方不触发追赶加速 |
| 直角盲弯 | 沿可信历史路线接近，在可安全观察的位置减速转向 | 不切墙角，不进入尚未确认的通道 |
| 人走到后方 | 先判断是否仍在绕障；需要掉头时验证完整转向空间 | 不因角度阈值无条件原地转身 |
| 输入短暂变差 | 仅在当前可验证路径与停车余量内继续，必要时减速或停止 | 停止动作可解释，恢复时不猛冲 |
| 目标失效、通道不可验证 | 停车等待 | 不继续盲目探索或自动向未知后方倒退 |

普通停止应平顺，突发危险时的制动优先于舒适性，不要求紧急制动也满足普通行驶的加加速度上限。

## 2. 目标从一个点升级为带时间的运动意图

现有 computeFollowTarget 主要根据距离误差计算速度，偏离目标方向后再减速。绕行增加距离时，这个结构容易产生较强追赶意图。

新增 TargetIntent，至少包含：目标在 odom 中的位置、采集时间、经过滤波的速度、位置/速度可信度、历史轨迹、有效性以及明确停止原因。目标位置必须使用采集时刻的机器人位姿变换，不能混用当前位置。速度不能由相邻原始 UWB 点简单差分；采用带异常值门控的状态估计，并在目标突变、输入迟滞或非视距质量变差时降低前馈权重。

在人、狗已处于同一可信跟随路线时，可用以下意图模型：

```text
期望跟随间隔 = 基础间隔 + 时间间隔系数 × 人的估计前进速度
参考速度 = 人沿参考路线的估计速度 + 有上限的间隔修正
```

间隔优先沿路线计算，避免墙两侧直线距离很近而误认为已经跟到。障碍绕行或路线拓扑发生变化时，不机械沿用该一维公式；保持阶段速度限制并重新关联目标进度。

“有上限的间隔修正”意味着掉队后允许略快一些接近，而不是距离越远越积极追赶。人的估计速度只产生意图，最终速度仍受感知、净空、曲率、制动与实际底盘能力限制。人停止时前馈逐步下降，并根据可用间隔规划停车。

跟随距离采用带迟滞的区间，减少人在边界附近晃动时的反复启停。任何最低距离或人体保护约束仍然独立生效；不能通过放大迟滞放弃近距离保护。

## 3. 路线连续性比逐帧最短更重要

目标历史轨迹用于引导转角和跟随方向，不能当作可通行证据。每段路线仍需双目地图与完整足迹检查。人能通过不代表机器人能通过，UWB 点之间的直线插值也可能穿墙。

局部搜索使用带朝向的状态格，维护绕障侧、中间目标以及当前可执行路径段。正常重规划保留仍有效的路径前缀；只有路径失效、障碍变化或替代路线收益明显时才更换。若原路径已经不安全，保持路线的偏好不能阻止立即停车或改道。

采用允许适度偏离中心线的通行走廊，由 MPPI 在走廊内生成符合运动约束的动作；不要求机器狗贴着离散折线行走。路径拼接和圆滑处理必须重新验证足迹扫掠，不能用几何平滑切穿墙角。

需要保持的是绕障侧和路线，不是角速度符号。一次左侧绕行可以先左转、沿边走，再右转接回。

## 4. 阶段管理不直接制造速度跳变

内部维护 FOLLOW、DETOUR、REJOIN、OBSERVE、WAIT 等阶段，但阶段之间只改变目标、约束和代价，不直接切换固定速度。

- FOLLOW：尽量匹配人的节奏，保留舒适间隔。
- DETOUR：跟踪绕行路径，在净空与曲率约束下连贯运动，抑制追赶补偿。
- REJOIN：路径已可接回时仍保留谨慎速度，确认后续通道后恢复跟随。
- OBSERVE：只执行已验证的观察运动；允许平缓转向，也允许停车观察。
- WAIT：无可验证运动或目标失效时停车，恢复须满足输入与路径条件。

进入风险更高的状态允许立即收紧约束；恢复加速使用迟滞和连续变化。不要仅凭计时器到期退出绕障。通过条件应包含机身已通过障碍、接回路线可行、后续通道观测足够新鲜。

## 5. 速度、加速度和加加速度共同设计

速度上限来自以下约束的共同作用：

```text
人体间隔与目标可信度
路径前方的曲率与转弯空间
障碍净空和可观测距离
输入年龄与运动状态估计误差
绕障/接回/观察阶段
底盘实际执行与制动能力
```

限速应有前瞻：为即将到来的弯道或狭窄段提前减速，不能到限制边界才突然降低目标速度。根据曲率与障碍距离调速可参考 [Nav2 RPP 官方说明](https://api.nav2.org/nav2-humble/html/md_nav2_regulated_pure_pursuit_controller_README.html)；本项目继续使用 MPPI，可将同类约束纳入速度剖面。

普通运动中限制线/角速度、线/角加速度以及加速度变化率，减少纵向窜动和突然甩头。MPPI 的平滑项覆盖跨控制周期的首条命令变化，不仅平滑预测时域内部。

统一命令执行模型需要同时记录实测速度、上一条命令和当前加速度状态。候选序列从相同执行语义展开，死区、响应滞后和限幅进入预测。最终发布的命令应与已验证序列一致；若末端确实修改，必须重新校验。不能只追加速度平滑节点后就认定轨迹仍然安全。

## 6. 底盘低速能力是实施前的关键事实

当前配置将非零线速度最低值设为 0.25 m/s，源码在普通加速度限幅后仍可能直接抬升到此值。这会限制细腻起步和贴近目标时的连续低速运动。该值包含 Lite3 平台假设，不能未经核对用于 Go2。

需在实际 Go2 控制模式中测量：稳定最低前进速度、最低可控角速度、起步延迟、停止延迟、减速度以及行走状态切换行为。

若底盘支持稳定低速，采用实测连续可执行范围；若存在明显的站立到行走死区，必须显式建模并采用起停迟滞，不能用高频开关速度模拟慢走，也不能把安全上限之下的速度抬高。上层规划可以改善走路路线与节奏，但不能保证改变厂商底层步态的迈步形态。

## 7. 如何验证自然与安全

先记录基线，再在同一组路线和目标运动下比较，不以单次“成功绕过去”作为通过。

| 指标 | 应观察的改善 |
| --- | --- |
| 实测跟随间隔 | 匀速跟随时稳定，停走过程不持续振荡 |
| 实测速度和加速度 | 普通起停无明显突变，绕障退出无追赶峰值 |
| 角速度反向次数 | 同一障碍旁不反复左右犹豫；允许正常接回所需的反向 |
| 普通停车与起步次数 | 已知开阔路线内不因测量抖动反复停走 |
| 障碍净空 | 使用完整机身/腿部包络评估，不能只检查路径中心线 |
| 观测约束 | 不因无障碍点或地图过期而进入未知区域 |
| 执行一致性 | 实际发布命令对应已校验轨迹，暖启动与回退也遵守当前约束 |
| 失败行为 | 无观察空间、目标失效、输入延迟时稳定停车，无循环恢复动作 |

具体数值门槛应由真实底盘响应、感知延迟、相机覆盖及场地要求确定，不能把尚未实测的加速度或净空参数当成保证。

## 实施顺序

1. 修复现有执行一致性、暖启动限速和最低速度语义，确认真实 Go2 底盘参数。
2. 在无障碍场景实现运动趋势前馈、间隔区间和连续起停，先让普通跟随自然。
3. 增加可信自由空间、带朝向局部路径和路径连续性，再接入绕障/接回阶段。
4. 增加观察与等待决策，覆盖盲弯和目标到后方。
5. 用直线停走、小幅横移、单障碍、连续障碍、长横障、直角盲弯和输入中断逐项验收。

这些步骤共用一套目标意图、约束和执行模型，不分别给每种场景堆叠独立速度补丁。
