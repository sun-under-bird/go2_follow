# Go2 UWB 跟随避障实机问题复盘（2026-09-15）

## 结论

当前 `feature/uwb-random-roam` 已通过编译和自动化回归测试，但实机跟随效果仍未验收通过。
最近一轮主要问题是：线速度恢复后，机器人在行进中转向不够灵活，目标横向移动时朝向跟不上；
继续单独增大角速度相关参数容易重新出现转过头和左右抖动。

自动化测试结果为 `243 tests, 0 errors, 0 failures, 25 skipped`。这只能证明代码边界和安全回归
没有明显错误，不能代替底盘、UWB、双目相机共同运行时的实机闭环验收。

## 当前未解决的问题

### 1. 行进中角度跟踪效果不好

- 80.2°以内已取消平滑线速度降速，机器人保持距离控制产生的前进速度并同时转向。
- 线速度可能达到 `0.80 m/s`，完整链路角速度上限为 `1.50 rad/s`，但底盘实际角速度存在启动死区、
  响应延迟和跟踪误差。
- 当前实机表现为机器人更愿意向前走，转向对人的横向移动响应不足。
- 这说明“完全不降线速度”和“快速跟上角度”存在耦合，仅调大角速度不一定能解决，反而可能恢复抖动。

### 2. 提前刹车参数在“转过头”和“转向迟钝”之间冲突

旧实机参数：

```yaml
turn_response_delay: 0.60
angular_braking_accel: 1.00
angular_brake_release_speed: 0.06
```

实际角速度为 `0.80 rad/s` 时，旧参数会得到约 `0.88 rad（50.4°）` 的动态停止角，目标还偏离很大时
就会撤掉角速度并锁住零命令，因此表现为不愿转弯。

当前试验参数：

```yaml
turn_response_delay: 0.20
angular_braking_accel: 1.50
angular_brake_release_speed: 0.08
```

相同实际角速度下动态停止角缩小到约 `0.453 rad（26.0°）`。该参数已经不再像旧值一样过早刹车，
但用户反馈整体实机效果仍不好，因此不能视为最终标定值。

### 3. Go2 存在线速度和角速度执行死区

- 实测约低于 `0.25 m/s` 的线速度只会调整重心，不一定形成稳定步态。
- 实测约低于 `0.40 rad/s` 的角速度不一定产生明显转向。
- 原规划器每周期都从 `/odom_leg` 实测速度重新限速，曾导致角速度长期卡在 `0.075 rad/s`、
  线速度长期卡在 `0.25 m/s`。
- 当前已改为同向加速时沿上一周期命令累积；降速、停车和反向仍以实测速度为安全基准。
- 这项修改解决了“命令永远跨不过死区”的代码问题，但不能消除底盘本身的非线性响应。

### 4. 感知偶发超时会插入零速度

现场曾捕获：

```text
planner state: SENSOR_TIMEOUT
obstacle_age_sec: 0.717
obstacle_timeout_sec: 0.70
```

此时规划器会立即输出零速度。它不是持续慢速的主要原因，但会造成跟随过程中偶发停顿。
当前保留该安全保护，没有通过增大超时阈值掩盖相机或点云断流。

### 5. 反光区域仍可能产生伪障碍

- 当前障碍高度范围扩大为 `0.08～0.65 m`，可以覆盖更完整的低矮和较高障碍，但也会接收更多候选点。
- 反光表面的视差噪点仍可能进入滚动地图。
- `test/reflective-noise-filtering` 分支包含针对反光噪点和连续帧确认的试验方案，应在该分支继续实机对比。

## 本轮已经实施的修改

1. 障碍点高度范围从 `0.10～0.50 m` 改为 `0.08～0.65 m`，同步修改默认值、文档和测试。
2. 跟随与规划最小非零线速度改为 `0.25 m/s`。
3. 最终角速度改为从上一周期真实下发命令连续累积，候选评分方向历史与真实命令历史分离。
4. 最终线速度只在同向加速时从上一周期命令累积；降速、零速和反向继续使用实测速度保护。
5. 删除 80°以内的方位角平滑降速，`heading_stop_angle` 改为 `1.40 rad（80.2°）`。
6. 提前刹车参数调整为 `0.20 s / 1.50 rad/s²`，刹车释放阈值改为 `0.08 rad/s`。
7. 局部规划角加速度上限从 `1.50` 改为 `2.00 rad/s²`，角速度上限仍为 `1.50 rad/s`。
8. UWB TF 等待和里程计超时适当放宽到 `0.20 s`，减少短暂调度延迟造成的误停。

## 已确认的诊断证据

空旷且目标距离约 `3.04 m` 时曾捕获：

```text
avoidance_active: false
selected_speed_scale: 1.000
nominal_v: 0.800
planned_v: 0.800
final_v: 0.250
measured_v: 0.129
```

这证明当时慢速不是避障主动降速，而是最终线速度限幅反复从低实测速度开始，无法跨周期爬升。

另一阶段目标方位约为 `1.20～1.25 rad（69～72°）`，旧代码仍在停止角之前执行平滑降速，名义线速度
下降到 `0.25～0.37 m/s`。该平滑逻辑已经删除，但删除后暴露出高速前进与转向能力不足之间的矛盾。

## 下一轮建议

1. 在测试分支录制同一条固定路线，分别做直行、30°、60°、80°和180°目标切换。
2. 每轮只改一个因素，避免同时修改角速度 Kp、角加速度和刹车参数后无法判断因果。
3. 首先判断转向迟钝发生时是 `desired_wz` 本身太小、动态刹车锁零，还是最终命令已足够但
   `/odom_leg.actual_wz` 跟不上。
4. 如果高速前进时实际角速度始终跟不上，应考虑“大角度离散限速档”而不是恢复连续平滑降速：
   例如 0～45°保持完整线速度，45～80°固定一个较低但可迈步的速度，超过80°原地转向。
5. 如果最终角速度已达到上限而实际角速度仍低，应检查 Go2 运动模式、底盘桥接和线角速度耦合，
   继续增大软件 Kp 不会解决底盘能力限制。
6. 对 `SENSOR_TIMEOUT` 单独统计发生频率；只有确认是正常帧率抖动后，才考虑调整超时参数。

## 经验沉淀

- 必须同时记录名义速度、规划速度、最终命令和实测速度；只看 `/cmd_vel` 无法定位问题层级。
- 机器人底盘存在执行死区时，不能每周期只从低实测速度重新生成加速命令，否则命令永远无法爬升。
- 加速可以使用历史命令保持连续性，但减速、急停和方向切换必须保留实测速度和碰撞预测作为安全依据。
- 动态刹车的延迟项和制动距离项会随实际角速度快速增大，过度保守会表现为“不愿转弯”。
- 取消转弯降速会提高跟随速度，但也会放大底盘线角速度耦合；“速度快”和“转向灵活”需要联合实机标定。
- 自动化测试用于防止软件回归，最终参数是否可用必须由可复现路线和同步数据记录来判断。
