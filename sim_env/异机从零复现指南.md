# 另一台电脑从零复现 Go2 跟随仿真

更新日期：2026-10-08。适用仓库：<https://github.com/sun-under-bird/go2_follow>，分支：`codex/follow-sim-speed-fixes-20261008`。

本文从 Windows / WSL 开始，覆盖安装、通信检查、网页操作、八场完整跟随验收、离线回放、停止、更新和备份。建议先完成第 1～6 节，再手动体验第 7 节，最后运行第 9 节的完整检查。

## 1. 先明确复现的对象

### 1.1 能复现什么

这是 **Windows x64 + WSL 2 + Ubuntu 22.04 + ROS 2 Humble + MuJoCo** 的平地跟随实验台。新电脑只需计算机，不需要接 Go2、D435i 或 UWB。

运行链路为：

```text
有效 UWB 目标历史 → 局部跟随目标区域
前视深度 → 滚动观测地图 → 位置/朝向 Dijkstra 搜索
目标区域 + 局部路径 → Nav2 MPPI 路径、速度与停车评分
平滑与矩形碰撞/停车复查 → ONNX 步态策略 → MuJoCo
```

环境也包含 Unitree SDK、Go2 URDF、CAPO 里程计的独立通信演示。**跟随实验台当前使用真值里程计，独立 CAPO 演示通过不代表跟随控制已经使用 CAPO。** 仓库 `src/` 保留的实机 ROS 包与 `sim_env/` 实验算法是两套实现；本文不提供已经完成的 RK3588 实机部署。

### 1.2 当前效果与配置基准

算法代码基线为 `5460dfdc071a01775196d2b7956dc2c533698179`。本指南所在后续提交补齐异机安装问题；**安装时使用包含本指南的提交，不要退回该旧提交执行从零安装**。克隆后保存实际 `git rev-parse HEAD`，后续按这个提交重建，避免分支以后更新造成版本漂移。

| 项目 | 本轮完整检查配置 |
| --- | --- |
| 人的速度 | 0.80 m/s |
| 机器狗前进请求上限 | 0.80 m/s；实际速度另外测量 |
| 转向请求上限 | ±1.00 rad/s；不等同实际转速 |
| 碰撞包络 | 长 0.70 m、宽 0.32 m 的矩形 |
| 五项运行模式 | `rate / trail / camera / steady / process` |
| 相机俯角 | **显式设置向下 25°**；启动默认仍为 0° |

2026-10-08 保存的同版八场结果为 **6/8 完整通过**：开阔、长横墙、连续障碍、直角盲弯、封闭停车、方形回环通过；交错回环未完整完成且掉队，双长墙回环完成两圈但最大间距超标。详见[完整报告](artifacts/速度跟随修复与验收_20261008.md)与[原始八场回放](artifacts/navigation-speed-history32-20261008-验收回放.html)。**这不是八场全过的交付，也没有证明多次运行成功率。** 新电脑调度和 MPPI 采样会影响结果，应重新验收。

相机红外双目基线 0.050 m、垂直视场 58°、424×240 图像，以及机身安装中心 `[0.23, 0.025, 0.135] m` 是当前仿真设置；25°也是安装试验值，不能代替实机标定。深度理想、里程计为真值，UWB 未含完整 NLOS/多径/人体遮挡；场景只覆盖平地静态障碍。未做低速死区、起步响应补偿。

## 2. 新电脑准备与目录约定

### 2.1 主机要求

推荐 Windows 11 x64，开启 BIOS/UEFI 的 CPU 虚拟化。本文安装脚本下载 `linux-x86_64` MuJoCo，因此不适用于 Windows ARM 或 RK3588。

工程建议：至少 16 GB 内存，32 GB 更方便；给 WSL 磁盘预留至少 50 GB 可用空间，另留验收日志和导出备份空间。这是资源建议，不是已经测出的最低配置。第一轮关闭其他大负载任务，避免把主机卡顿误判为跟随算法退化。

原生 MuJoCo / RViz 窗口需要 WSLg 和对应 Windows 显卡驱动；网页验收默认 OSMesa 离屏渲染，不必安装完整 Linux 桌面。WSLg 官方支持 Windows 11 或 Windows 10 build 19044 及以上，使用 WSL 2；驱动安装在 Windows。参见 [Microsoft WSL 图形应用说明](https://learn.microsoft.com/en-us/windows/wsl/tutorials/gui-apps)。

### 2.2 本文的路径

| 位置 | 示例 | 可以修改吗 |
| --- | --- | --- |
| Windows Git 仓库 | `C:\go2\go2_follow` | 可以，后面 `Set-Location` 使用自己的路径 |
| Ubuntu 虚拟磁盘 | `D:\WSL\Ubuntu-22.04` | 可以，例如 `C:\WSL\Ubuntu-22.04` |
| WSL 发行版名称 | `Ubuntu-22.04` | 本文固定此名，启动/验收脚本也使用此名 |
| Linux 用户 | `chy` | 本文固定此名，由脚本创建，与 Windows 用户名无关 |
| Linux 运行目录 | `/home/chy/go2_sim` | 本文固定此目录 |
| 安装脚本快照 | `/opt/go2-env-setup` | 安装时自动复制，供恢复步骤使用 |

Windows 用户不用叫 `chy`，也不用有旧电脑的 Documents 目录。不需要复制旧电脑的绝对路径，不需要删除已有 Ubuntu 26.04，不需要改动 Docker 的发行版。若新电脑已经存在同名 `Ubuntu-22.04`，脚本会继续配置它；应先确认其中没有需要保留的不同开发环境。

本文每段命令标注运行位置。PowerShell 提示符通常以 `PS` 开头，Ubuntu 终端使用 Bash；在 Ubuntu 输入 `exit` 可返回原 Windows PowerShell，也可以另开 PowerShell。不要把 `source`、`~/go2_sim` 等 Linux 命令直接粘到 Windows。

后续代码以 **Git 仓库里的 `sim_env/` 为准**。旧电脑顶层 `go2_slam 2/sim_env` 是历史副本，与本仓库不同步。只有浏览回放需要历史文件，开发与更新应从本仓库执行。

### 2.3 安装 Git 并克隆指定分支

先从 [Git 官方 Windows 安装页](https://git-scm.com/install/windows)安装 Git，选择允许命令行使用 Git，安装后重新打开 PowerShell。

**运行位置：普通 Windows PowerShell。**

```powershell
git --version
New-Item -ItemType Directory -Force -Path 'C:\go2' | Out-Null
git clone --branch codex/follow-sim-speed-fixes-20261008 --single-branch https://github.com/sun-under-bird/go2_follow.git 'C:\go2\go2_follow'
if ($LASTEXITCODE -ne 0) { throw '仓库克隆失败，先处理 Git 网络或登录错误。' }
Set-Location -LiteralPath 'C:\go2\go2_follow'
git status --short --branch
git rev-parse HEAD
Test-Path -LiteralPath '.\sim_env\native\go2_follow_mppi_critics\CMakeLists.txt'
```

最后一项应为 `True`；Git 当前分支应正确，安装前不应有个人修改。目标目录已存在时先检查其内容，不要覆盖或删除。公开仓库只读克隆通常无需凭据；以后推送个人修改需要你自己的 GitHub 权限。

## 3. 安装并检查 WSL 2

**运行位置：以管理员身份打开的 Windows PowerShell，使用同一 Windows 账户提升权限。**

新电脑尚未安装 WSL 时执行：

```powershell
wsl --install --no-distribution
```

按提示重启 Windows。已经安装 WSL 的电脑跳过这条。重启后继续：

```powershell
wsl --update
wsl --set-default-version 2
wsl --version
wsl --status
wsl --list --online
```

确认在线列表里有 `Ubuntu-22.04`。暂时没有 Linux 发行版是正常的，下节脚本会创建。安装选项 `--web-download`、`--no-launch` 和 `--location` 需要当前 WSL 支持；不支持时先更新 WSL。版本、发行版列表、安装与导入命令依据 [Microsoft WSL 命令文档](https://learn.microsoft.com/en-us/windows/wsl/basic-commands)。

若 Microsoft Store 更新受阻，可用 `wsl --update --web-download`。出现虚拟化不可用或系统要求重启时，先解决这一层，不要继续运行 Ubuntu 安装脚本。

## 4. 一次安装 Ubuntu、ROS 和仿真依赖

### 4.1 执行安装入口

**运行位置：管理员 Windows PowerShell，仓库根目录。** 新电脑没有 D 盘时修改下面的安装位置。

```powershell
Set-Location -LiteralPath 'C:\go2\go2_follow'
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\sim_env\Setup-Wsl.ps1 -Distribution Ubuntu-22.04 -InstallLocation 'D:\WSL\Ubuntu-22.04'
```

执行策略只对当前 PowerShell 进程生效；受组织策略限制时按组织要求处理。不要在安装期间修改源码。下载、APT 和首次本机构建需要时间，查看日志判断进度，不以某个固定分钟数判定失败。

脚本失败会抛错并保存日志。**有红色失败信息时不要直接跳到网页启动**，先按第 13 节恢复。新环境安装会在 WSL 内构建必要的上游 SDK、仿真、ROS 适配包和小型 MPPI 原生插件；Windows 本身不需要 ROS，本文不要求在 Windows 编译仓库 `src/` 的实机包。

### 4.2 安装实际做了什么

| 阶段 | 内容 | 日志位置（Windows 仓库内） |
| --- | --- | --- |
| 创建发行版 | 下载 Ubuntu 22.04，放到指定磁盘目录 | `sim_env/logs/wsl-install.log`，已有发行版则跳过 |
| 复制安装资源 | `scripts / locks / config / follow_demo / native` 全部复制到 `/opt/go2-env-setup` | `prepare-directory.log`、`copy-bundle.log` |
| 基础安装 | Ubuntu 更新、用户 `chy`、systemd、Humble、Nav2、图形库和构建工具 | `ubuntu-ros-bootstrap.log` |
| 仿真栈安装 | 固定提交源码、Python venv、MuJoCo、Unitree、CAPO、Go2、MPPI 插件 | `go2-stack-install.log` |
| 环境检查 | ROS 消息、图像转换、ONNX、物理/渲染、跨进程 DDS | `environment-check.log` |

每个日志实际位于 `sim_env/logs/`。Linux 详细构建日志在 `~/go2_sim/logs/`，依赖清单在 `~/go2_sim/locks/`。APT 默认使用中科大 Ubuntu/ROS 镜像，仍核验官方签名。

创建用户时会设置本地 `sudo` 免密码，写入 `/etc/wsl.conf` 的默认用户与 systemd 配置，不启用 SSH；基础安装也会更新该发行版系统包。安装末尾将 `Ubuntu-22.04` 设为默认发行版。

本指南配套修正了几个从零安装缺口：复制 `native` 源码；先启用 universe，再安装 `libxtensor-dev / libxsimd-dev / xtl-dev` 和中文字体；图形不再默认指定 NVIDIA；原生插件统一从 Linux 固定源码目录构建。插件摘要包含源码相对路径与主要 ABI 依赖版本，避免 `/opt` 首装与 Windows 日常更新冲突。仓库保存的旧 `.so` 仅作历史证据，新电脑会本机构建。

### 4.3 确认 WSL 版本并重新进入

**运行位置：Windows PowerShell。**

```powershell
wsl --list --verbose
```

`Ubuntu-22.04` 应显示 `VERSION 2`。若已有发行版是 WSL 1，停止其中的工作、备份后再执行 `wsl --set-version Ubuntu-22.04 2`。

首次配置 `/etc/wsl.conf` 后，需重新启动该发行版让默认用户/systemd 设置生效。确认该发行版没有其他工作、所有演示已结束，再执行：

```powershell
wsl --terminate Ubuntu-22.04
wsl -d Ubuntu-22.04 -u chy
```

这一步只用于首次配置或系统恢复；日常关闭网页演示使用第 8 节停止脚本。无需 `wsl --shutdown`，它会影响其他发行版。

## 6. 独立 SDK → ROS → CAPO 与模型可视化

本节用于确认额外环境链路。网页跟随验收无需同时运行这一套。

### 6.1 自动链路检查

**运行位置：Ubuntu 终端；先关闭其他本实验台/原生演示。**

```bash
source ~/go2_sim/setup.bash
go2-check-native
cat ~/go2_sim/artifacts/native-integration-check.json
```

约 25 秒的演示会打开原生 MuJoCo，启动站立策略、LowState 适配和 CAPO，结束时清理自己创建的进程。应看到 `passed: true`、LowState/IMU/Odom 持续接收、非有限值计数为 0、策略进程在检查期间存活。它检查站立与消息链路，不验证里程计精度、行走或跟随。

### 6.2 手动查看原生模型

开三个 Ubuntu 终端，每个终端先执行 `source ~/go2_sim/setup.bash`，然后分别运行：

| 终端 | 命令 | 用途 |
| --- | --- | --- |
| 1 | `go2-sim` | 原生 MuJoCo 物理模型窗口 |
| 2 | `go2-policy 30 0 0 0` | ONNX 站立策略；交互方式可改成 `go2-policy --teleop` |
| 3 | `go2-capo` | 适配 LowState 并运行 CAPO |
| 可选 4 | `go2-rviz` | URDF 与关节滑条检查 |

只有模拟器、没有策略时会受重力运动。`go2-rviz` 是独立 URDF 显示，关节滑条不控制 MuJoCo。原生演示与网页跟随入口各自独立；不要再启动实机 Sport 接口尝试让原生窗口读取网页命令。

手动演示结束时，先在终端 1 `Ctrl+C` 停止模拟器，再依次停止策略、CAPO、RViz，确认相应终端返回提示符。不应只关策略留下模拟器继续执行最后一帧命令。

## 7. 启动网页并人工验收

### 7.1 启动当前完整验收的配置

**运行位置：普通 Windows PowerShell，仓库根目录。** 每开一个新的 PowerShell，重新进入仓库；需要时重新设置进程级执行策略。

```powershell
Set-Location -LiteralPath 'C:\go2\go2_follow'
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\sim_env\Start-FollowDemo.ps1 -ExecutionMode rate -PlanningMode trail -ObservationMode camera -ExecutorWakeMode steady -SearchExecutionMode process -CameraPitchDeg 25
```

脚本后台启动 WSL 服务，检查身份后打开 `http://127.0.0.1:8765/`。Ubuntu 内实际命令是 `go2-follow`；手动运行时同样要指定配置，否则俯角默认 0°。

Windows 浏览器通过 localhost 访问 WSL 网络应用的方式参见 [Microsoft WSL 网络说明](https://learn.microsoft.com/en-us/windows/wsl/networking)。本文不要求修改为 mirrored 网络，也不要求关闭防火墙或把服务暴露到局域网。

启动脚本会核对已有服务的应用身份、五项模式和俯角；相同实例可复用，配置不同时会拒绝。**`Start-FollowDemo.ps1` 不复制新代码**，改代码或拉取更新后按第 12 节安装再启动。

### 7.2 页面操作顺序

1. 选择一个场景，点击“载入场景并重置”，等待姿态就绪。
2. 保持暂停，确认起点周围半径 **1.2 m** 无障碍，再点击“确认起始周围 1.2 m 净空”。这是启动时的人工确认，不是把机身改回圆形；相机无法看到全部脚边。
3. 检查目标速度为 **0.80 m/s**，点击“开始 / 恢复跟随”，再点击“目标沿场景路线行走”。只点开始不会自动让人沿路线走。
4. 看黄色局部路径、有限观测地图、紫色停车预测以及机器人实测速度/间距。完整场景中的障碍只供显示，规划读取的是实际观测地图。
5. 让场景走完整段或至少两圈，观察是否掉队、缺失回环、连续原地转向或反复长停。
6. 可中断深度或 UWB，观察指令归零；恢复后再次检查状态与目标有效性。可下载 CSV。

人在仿真中没有身体碰撞动力学。地图点击目标可能让人穿过障碍，正式避障验收用预置路线。每次重置会清空地图、跟随历史和起始确认。切换俯角/运行模式必须停止后重启。

| 场景参数名 | 页面/测试含义 |
| --- | --- |
| `open` | 开阔直行 |
| `long_wall` | 长横向障碍绕行 |
| `consecutive` | 连续交错障碍 |
| `corner` | 直角盲弯 |
| `blocked` | 封闭通道：期望停止，而非撞穿或绕出墙外 |
| `square_loop` | 方形路线连续四个直角，两圈 |
| `slalom_loop` | 四组交错障碍回环，两圈 |
| `wall_loop` | 双长墙绕行回环，两圈 |

## 9. 完整多场景自动验收

### 9.1 先运行一场检查环境

关闭人工实例，然后执行。每轮前缀必须唯一，只用小写字母、数字、短横线，不超过 64 字符。

**运行位置：Windows PowerShell，仓库根目录。**

```powershell
.\sim_env\Check-NavigationDemo.ps1 -Scenarios open -Speed 0.8 -CameraPitchDeg 25 -ReportPrefix navigation-pc2-open-a
```

脚本先安装仓库当前的实验台源码及原生插件，再启动自己的实例、检查、保存并停止。开阔速度 0.8 的运行段约 19 秒，初始化/检查/退出另占时间。**检查期间不要点击网页或再启动另一场测试。**

### 9.2 八场完整检查

```powershell
$go2Scenes = @('open', 'long_wall', 'consecutive', 'corner', 'blocked', 'square_loop', 'slalom_loop', 'wall_loop')
.\sim_env\Check-NavigationDemo.ps1 -Scenarios $go2Scenes -Speed 0.8 -Laps 2 -ExecutionMode rate -PlanningMode trail -ObservationMode camera -ExecutorWakeMode steady -SearchExecutionMode process -CameraPitchDeg 25 -ReportPrefix navigation-pc2-full-a
```

脚本依次运行，不并行。基础场景最长 90 秒，循环场景按真实预置路线长度、速度、圈数计算并加 10 秒跟随余量。整轮至少数分钟，实际时间取决于新电脑。失败场景保留非零退出码，但正常流程仍会继续下一场、保存证据并在每场结束后清理；安装、启动等异常则可能中止整轮。

**已有版本存在两个完整失败场景，因此最后出现“存在未通过场景”可能正是复现了算法边界，不是环境未安装。** 查看报告区分启动失败、基本保护失败、任务没完成与流畅性失败。不要为了让表格全绿而删掉失败场景或降低门槛。

需要水平安装对照时，另开一轮、改 `-CameraPitchDeg 0` 与新前缀；不能混用两轮配置和结论。

### 9.3 报告与判据

报告 schema 7 将基本保护、任务完成和流畅性分开。完整通过需全部适用项目通过：

| 检查 | 门槛 / 含义 |
| --- | --- |
| 基本保护 | 碰撞、姿态、请求速度上限、MPPI 有效，以及深度/UWB失效停车等 |

| 慢行占比 | `abs(vx) < 0.05 m/s` 的适用移动段时间比例不超过 15% |
| 最长慢行/停顿 | 单段不超过 2 秒 |
| 移动跟随间距 | 最大严格小于 3.5 m |
| 循环完成 | 人和机器人按顺序经过要求的门点并完成指定圈数 |
| 封闭通道 | 检查稳定停车；移动速度与绕行流畅性不适用 |

实际条件、统计区间与字段以 [检查源码](follow_demo/tests/check_navigation_demo.py)为准。不要把整个场景含结束等待的平均速度当成移动段成绩；也不要把测试末尾主动中断数据导致的停车当成过程中无理由停车。

每场生成 `<前缀>-<场景>.json`、`<前缀>-<场景>-samples.json`。Windows `sim_env/artifacts/` 还保存每场 MPPI 日志和 `<前缀>-suite-exit-codes.json`，Linux原始数据在 `~/go2_sim/artifacts/`。报告记录运行身份和运行源码摘要，比较时先核对这些字段。

**运行位置：Windows PowerShell，仓库根目录。**


## 13. 安装失败恢复与排查

### 13.1 按阶段恢复，而不是全部重装

Windows 查看相关阶段日志尾部：

```powershell
Get-Content -LiteralPath '.\sim_env\logs\ubuntu-ros-bootstrap.log' -Tail 80
Get-Content -LiteralPath '.\sim_env\logs\go2-stack-install.log' -Tail 80
Get-Content -LiteralPath '.\sim_env\logs\follow-demo-stderr.log' -Tail 80
```

没有产生某个日志时说明还未进入那一阶段，`Get-Content` 文件不存在不等同新的安装错误。先保存失败日志，确定网络/包版本/源码/图形哪一层失败；确认安装已停止后再重试。

完整脚本允许继续配置已存在的 `Ubuntu-22.04`，但会再执行 APT 更新。若只是上游源码或 Python 下载中断，可从已经复制好的安装快照恢复：

```powershell
wsl -d Ubuntu-22.04 -u chy --exec bash /opt/go2-env-setup/scripts/install_go2_stack.sh
if ($LASTEXITCODE -ne 0) { throw '仿真栈恢复仍失败，保存输出。' }
wsl -d Ubuntu-22.04 -u chy --exec bash /home/chy/go2_sim/bin/go2-check
```

该恢复依赖基础安装已经完成、`chy` 已创建、快照已经复制。安装器核对已有上游提交，版本不同会停止，避免静默覆盖。先处理具体版本差异，不应强行删除 `third_party`。

### 13.2 镜像故障时切回官方源

安装快照存在后可执行下列**替代基础安装步骤**；这是再次运行基础安装，会更新系统包：

```powershell
wsl -d Ubuntu-22.04 -u root --exec env GO2_UBUNTU_MIRROR=https://archive.ubuntu.com/ubuntu GO2_ROS_MIRROR=http://packages.ros.org/ros2/ubuntu bash /opt/go2-env-setup/scripts/bootstrap_ubuntu.sh
```

成功后再执行上一节的仿真栈恢复。通过 WSL `env` 明确传递参数，不能假设 Windows `$env:` 自动成为 Linux 变量。不要通过关闭 TLS/签名验证解决下载错误。

### 13.3 常见问题

| 现象 | 根因方向与处理 |
| --- | --- |
| 不认识 `--location` / `--no-launch` | 更新 Store 版 WSL 并检查 `wsl --help`。暂不能指定安装路径时，可先 `wsl --install -d Ubuntu-22.04 --web-download --no-launch`，再运行 Setup；已有发行版不会按 InstallLocation 自动迁移 |
| WSL 安装 0% 或发行版下载失败 | 使用 `--web-download`，检查 GitHub/发行版下载网络，保存 `wsl-install.log`；不要改成未锁定的 Ubuntu 最新版 |
| 进入了 24.04/26.04 | 用 `wsl -d Ubuntu-22.04` 明确指定；ROS Humble 的这套包按 22.04 安装，不在另一系统上硬套 |
| 找不到用户 `chy` | 基础安装未完成；查看 bootstrap 日志。Windows 同名用户不影响 Linux 用户创建 |
| Bash 报 `$'\r'` / `bad interpreter` | 源脚本被其他工具转为 CRLF；重新获取仓库原始文件，保留 `.gitattributes` 的字节约定，不要批量改运行源码换行后宣称同版 |
| CMake 找不到 xtensor/xsimd/xtl | 检查 universe 与三个 `-dev` 包；本指南版本已在基础安装中补齐 |
| `native/.../CMakeLists.txt` 不存在 | 拷贝不完整或仍使用旧 Setup；必须复制完整 `sim_env`，本版本会将 native 纳入快照 |
| CMake 提示 source 与缓存不一致 | 旧版本使用移动的源路径。运行本版本 `install_follow_demo.sh`，改用固定 `~/go2_sim/native`；不要复用其他电脑的 build 目录 |
| 插件加载失败、符号错误或 Nav2 `std::bad_alloc` | 首先查 Nav2/xtensor/xsimd 版本、插件是否本机构建、配置日志；以新机器对应头文件重建，不能复制旧 `.so` 绕过 ABI 问题 |
| Python 依赖找不到版本/下载失败 | 核对 Ubuntu Python 3.10、完整锁定清单、PyPI/镜像网络；不要任意解除锁定，先保存 pip 原始错误 |
| `cv_bridge` / NumPy ABI 错误 | 加载 `setup.bash` 中的独立 venv，保持 NumPy 1.26.4；不要混用系统 `pip` 或 NumPy 2 |
| ROS 节点创建失败 / 互相收不到消息 | 检查环境和 DDS 域；基础入口域 1，跟随域 42。不要叠加 `ROS_LOCALHOST_ONLY=1`，不要把 SDK 的 `/opt/unitree_robotics/lib` 加入 ROS 全局 LD_LIBRARY_PATH |
| 页面打开但一直等待 / 点击无效 | 先请求 `/api/state`；离线 HTML 不能发控制指令。查看 stderr、姿态就绪、起始确认、暂停和目标路线开关，检查 MPPI 子进程日志 |
| 8765 已占用或身份不同 | 正常停止自己的旧实验台；脚本拒绝占用其他应用。不要直接杀占端口的任意程序 |
| Windows 访问不到 localhost | 先检查 Ubuntu 内 `curl http://127.0.0.1:8765/api/state`，再定位 WSL 网络/Windows 代理；不先改成公网监听或关闭防火墙 |
| MuJoCo/RViz 窗口打不开 | 检查 WSLg、Windows 显卡驱动、DISPLAY；网页仍可用 OSMesa。新脚本不再指定 NVIDIA，不安装 Linux 显卡内核驱动解决 WSLg 问题 |
| 图表中文方块 | 检查 `fonts-noto-cjk`；渲染程序找字体后重新生成图表，原 JSON/samples 不受影响 |
| 原生模拟器启动后机器人倒下 | 先确认站立策略已启动；单独打开物理模型没有控制器，不是通信链路已通过 |
| 零碰撞却完整检查失败 | 看任务门点、圈数、实测速度与间距；稳定停车不能算完成绕障，已知 slalom_loop/wall_loop 仍有完整失败 |
| 较慢电脑出现更多停顿 | 比较采样年龄、控制周期、进程负载/日志与姿态，确认没有并行演示；不能只放宽安全约束来掩盖主机无法实时运行 |

其中 Nav2 原生评分器的依赖与几何等价说明见 [native/README.md](native/README.md)。日志最后的 `lo ... disabling multicast` 需要结合实际通信结果判断，不能仅这一条就宣称 DDS 不可用；RViz 的 `Stereo is NOT SUPPORTED` 与双目算法无关。

```powershell
if ($LASTEXITCODE -ne 0) { throw 'WSL 导出失败。' }
Get-FileHash -LiteralPath 'D:\WSL\backups\go2-jammy-configured.tar' -Algorithm SHA256
```

新电脑先安装/更新 WSL，再核对复制来的 tar 的 SHA256。如果尚无同名发行版：

```powershell
wsl --import Ubuntu-22.04 'D:\WSL\Ubuntu-22.04' 'D:\WSL\backups\go2-jammy-configured.tar' --version 2
if ($LASTEXITCODE -ne 0) { throw 'WSL 导入失败。' }
wsl --set-default Ubuntu-22.04

```

**不要为导入而直接注销一个已经有数据的同名发行版。** 先规划保留/备份；本文启动脚本使用固定发行版名称，随意改名后需要同步修改入口。

导出/导入和针对发行版的停止语义见 [Microsoft WSL 命令说明](https://learn.microsoft.com/en-us/windows/wsl/basic-commands)。
