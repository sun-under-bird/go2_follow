### 深度提交之前的等待

t=12.872～13.722，`depth_fusion.applied=92`、`rejected=1`、`last_worker_ms=51.4` 均不变；相机交付从 90 增至 97，pending 深度时间继续更新。t≈13.10 与 13.44 的 `busy=False`，说明并非融合任务持续运算或持续被拒收，而是新任务没有提交。pending 采集时间已早于控制时间，强烈指向精确采集时刻 TF 尚未进入缓冲区。旧代码吞掉 TF 异常，无法从旧报告进一步区分 TF 接收积压和其他提交前条件。

窗口版本误拒也是独立缺陷：旧 run t=15.38～16.02 的拒收数从 2 增至 4，并出现 MAP_STALE；地图跨越 0.1 m 整格就递增窗口版本，曾令正确采集时间 TF 生成的融合副本整帧重算。但最新 pulse open 的上述长停期间拒收数没有增长，仅修窗口版本无法声称已覆盖全部失速根因。

最新 open 控制回调采样耗时均值 76.5 ms、最大 150.8 ms，显著超过 20 ms 目标周期；传感器桥平均 18.0 ms、最大 140.0 ms。异步规划耗时均值 72.6 ms、最大 123.4 ms，不应仅凭相近数字认定搜索阻塞控制；需要控制回调分阶段计时确定主要计算部分。

### 连续障碍的另一个边界

pulse consecutive 的 239 个正式样本中 `observation.sequence` 最大值为 0，未执行观察任务，不能把该场停车归因于观察准入或看向。t=5.80、6.08、6.34 出现只有起点的单点参考，MPPI 动作 `last_result.status=4` 反复成功结束；短滚动参考和上层持续追踪需求存在语义差异，值得在调度修复后独立检查。较长绕行路径也出现 ODOM_STALE、MAP_STALE 和 CONTROLLER_STALE，现阶段不能用单点路径解释全部 6.26 s 控制等待。

后续应区分“真正到达人的保持区域”和“暂时到达局部滚动参考”：保证每段执行参考来自完整已知包络，并按实际可行前向进展延长；墙前确实缺少通道时仍进入原观察与停车流程。先用停车事件、TF 等待及动作结束证据定位，再评估目标选择或路径更新，保留绕墙能力和原安全门槛。

## 4. 本轮修复及为什么这样改

| 修改 | 解决的结构问题 | 不承担的结论 |
|---|---|---|
| `ExecutorPulse` 每 20 ms 以单调时钟调用执行器 wake；启动身份有 native / steady | 系统日期变化时，为 ROS 等待提供外部唤醒；可独立做同条件对照 | 不更改消息采集时间、ROS 仿真时间或保护门槛；没有自然回跳不能证明抗回跳效果 |
| 独立 `TfReceiver` 节点与执行器 | TF 接收无需排在耗时导航控制回调后面，减少新深度查不到采集时间外参的等待 | 只维护线程安全 TF 缓冲；所有 core、地图提交与最终命令仍由唯一控制线程修改 |
| odom 与 operator 订阅只保留最新一条 | 控制负载升高时，避免消费积压旧输入并把过期信息当作当前状态 | 不把旧 stamp 改成当前时间，不放宽 0.2 s 里程计失效门槛 |
| `CallbackTrace.previous_stages_ms` | 将控制回调总耗时分解，区分时钟读取、深度接入、核心计算、MPPI 更新和发布 | 阶段诊断本身不参与命令或失效判定 |
| `halt_counts` 与最近 32 条 `halt_events` | 记录状态进入次数与当时 odom/depth/controller age，补足低频页面和 CSV 漏掉的短停 | 计数是状态进入事件，不是每个保持零命令的控制周期 |
| 深度 `submit_reason=WAIT_CAPTURE_TF`、TF 等待计数和异常文本 | 让“相机有帧但融合不增长”的提交前等待可以直接验证 | 不以最新 TF 替代采集时刻 TF，不因等待刷新深度健康时间 |
| 区分窗口 version 与 `evidence_version`，允许仅布局变化时按世界坐标重对齐副本 | 滚动窗口移动不等于证据内容冲突，避免正常行驶误丢正确深度 | epoch、地图对象、起始确认、新证据内容、过期帧和被更新帧仍严格校验；新窗口边缘保持未知 |
| 完整线段接触格计算提速 | 减少控制线程安全轨迹检查的计算成本 | 已通过接触格与 allowed 判定一致性对照；局部短段基准不能直接换算为整条控制回调或物理流畅性提升 |

截至这些后续修改前，192 项逻辑检查通过。后续输入修复候选已冻结为 [continuous-input-source-20261005/source.zip](continuous-input-source-20261005/source.zip) 与 [22 文件 SHA256](continuous-input-source-20261005/source_sha256.json)，整合逻辑检查 197 项全部通过；Linux 日志为 `~/go2_sim/logs/continuous-input-unit-20261005.log`，Windows 副本 `sim_env/logs/continuous-input-unit-20261005.log` 在最终交付时同步核对。逻辑检查不能代替物理流畅性验收。

[接触格一致性与性能报告](segment-fast-equivalence-20261005.json) 及 [对应日志](segment-fast-equivalence-20261005.log) 对照了 49,846 条线段接触覆盖和 3,000 次 allowed 判定，结果一致；短段 `segment_clear` 基准中位数由 33.953 μs 降至 3.244 μs，约 10.47 倍。此结果只适用于报告所列短段分布，不能宣称整场控制或跟随速度提高 10.47 倍。

保留深度 0.9 s、MPPI 0.3 s、里程计 0.2 s、操作通信和执行看门狗 0.35 s 等现有门槛，不用扩大失效时间掩盖积压。
