# Go2 平地有限视野连续跟随实验台

新电脑从 WSL 开始请先读 [异机从零复现指南](../异机从零复现指南.md)。下面 Windows 命令从 Git 仓库根目录执行；运行代码以仓库内 `sim_env` 为准，旧电脑顶层同名目录与本仓库不同步。

当前链路：UWB历史形成跟随目标区域 + 前视深度滚动地图 → 独立进程位置/朝向Dijkstra局部搜索 → Nav2 MPPI联合路径、速度参考和停车评分 → 平滑及实际停车轨迹复查 → 仿真中高速线速度校准 + ONNX步态 → MuJoCo。人的默认速度 **0.8 m/s**，绕障和盲角允许减速或短停。实测运动和指令分开记录。

当前默认身份为 **rate / trail / camera / steady / process**，相机安装默认水平（`-CameraPitchDeg 0`）。`trail`沿人的有效历史和有限预测退后跟随间距形成目标区域，并将终点限制在当前进度前方的局部窗口；不要求机器狗精确经过人体拐点，也不把人体轨迹当作自由地图。`annulus`保留为显式对照。[速度修复与验收记录](../artifacts/速度跟随修复与验收_20261008.md)区分完整场景、试验配置及失败边界。单轮通过不能证明成功率或任意场景都流畅。

工作域为平地、静态障碍，当前相机为 D435i。仿真仍用真值里程计和理想深度，未完成 CAPO/VIO、RK3588 性能或实机验收。本轮不做低速死区和起步响应补偿。

2026-10-08最终八场复测使用32 m、512点有界人体历史，相机显式向下25°，完整结果 **6/8通过**。开阔稳态0.785 m/s；长横墙、连续障碍、直角盲弯、封闭停车及方形回环通过。交错回环仍差最后一道回环门并掉队，双长墙回环完成两圈但间距超标。[真实八场回放](../artifacts/navigation-speed-history32-20261008-验收回放.html)保留失败；俯角0°默认不能继承25°试验的成绩。

## 1. 手动启动、验收与关闭

在 Windows PowerShell 执行，或双击上一级的 `Start-FollowDemo.cmd`：

```powershell
.\sim_env\Start-FollowDemo.ps1
```

打开 [跟随实验台](http://127.0.0.1:8765/)。启动脚本复用已有本实验台实例，不启动第二个控制器。

默认启动 `rate / trail / camera / steady / process`，俯角0度。独立比较 `heading` 或原生执行器等待时，先结束现有实例，再显式指定 `-ExecutionMode heading` 或 `-ExecutorWakeMode native`；模式与相机俯角在启动后固定，脚本拒绝复用身份不同的实例。

规划模式为 `trail` / `annulus`，观察模式为 `cone` / `camera`；`trail`与`camera`为当前默认，`annulus`与`cone`保留为旧方式对照。向下25度安装试验示例：

```powershell
.\sim_env\Stop-FollowDemo.ps1
.\sim_env\Start-FollowDemo.ps1 -CameraPitchDeg 25
```

搜索默认 `process`，用 spawn 进程读取私有地图快照，启动前预热；`-SearchExecutionMode thread` 仅用于显式对照。切换任何模式前须结束现有实例，启动脚本会拒绝复用身份不同的服务。

`-CameraPitchDeg`范围0～40度，向下为正；MJCF渲染、ROS光学TF及原始IMU安装轴使用同一配置，报告核对每份采样的实际角度。水平相机在近处看不到地面，向下安装可能减少该盲区；这些角度及机身安装位置仍是显式仿真参数，不能代替实机标定。

执行器唤醒方式 `steady` 每 20 ms 用单调时钟唤醒 ROS 执行器，`native` 用于对照；它不修改传感器时间或停车门槛。执行、规划、观察、唤醒和搜索五项身份必须在报告中一致。启动成功不等于实验算法或观察动作已经通过。

1. 选择场景，点击“载入场景并重置”，等待机器人姿态就绪。
2. 保持暂停，确认起点周围 **半径 1.2 m** 没有障碍，点击“确认起始周围 1.2 m 净空”。预置场景预留该区域；相机无法确认全部脚边，因此起始确认必须由人负责。该按钮不能清除已观测障碍。
3. 目标速度默认 **0.80 m/s**，点击“开始 / 恢复跟随”和“目标沿场景路线行走”。界面目标速度可设为 0.05～0.80 m/s；这是人的运动速度，必须另看机器狗的实测速度。
4. 看有限观测地图、黄色路径、紫色停车预测、浅蓝观察区域，以及 MPPI 候选速度、最终限速、区域验证和相关新前沿计数。完整物理场景只供人工观察，不输入规划器。
5. 检查能否完整绕过障碍、是否持续掉队、是否反复长停。只见机器人移动或零碰撞，都不能判定跟随成功。
6. 点击“中断深度”或“中断 UWB”，检查命令归零；恢复数据后继续条件由地图、目标和执行约束共同决定。点击“下载 CSV”保存记录。

地图点击只改变虚拟目标终点。目标没有人体碰撞动力学，自由点击可能让它穿过障碍；障碍验收使用预置路线。切换或重置场景会清空地图、估计、观察任务和起始确认。

结束时点击“结束演示服务”，或执行：

```powershell
.\sim_env\Stop-FollowDemo.ps1
```

**仅关闭网页不会停止后台仿真。** 停止脚本核实 HTTP、实验台 Python 进程和专属 Nav2 MPPI 子进程均已退出；异常退出时按 PID、启动时刻和命令核对后清理本实验台子进程，不结束其他任务、整台 WSL 或 Docker。助手每次完成验证后也停止自己启动的测试和仿真，并交给用户自行启动验收。[2026-10-08退出与版本记录](../artifacts/navigation-speed-history32-20261008-final-audit.json)核对本轮八场版本及16个渲染/搜索工作进程退出，HTTP和实验台专属Nav2也已结束。

## 3. 为什么采用历史地图与异步搜索

2026-10-08增加目标、几何、执行与调度修复：

- `trail`用真实UWB历史解释转弯后的跟随方向，目标区周围仍使用同一矩形Dijkstra搜索。终点按当前进度限制在前方2.4 m窗口，避免人跑远后目标跳过未走完的障碍分支；人体顶点只是意图，允许地图选择安全捷径。运行历史保留有界32 m、最多512点，覆盖0.08 m采样预算：交错回环中欧氏间距很小，折线进度却可能落后超过旧12 m，不能提前删掉未完成分支。地图大小及自由证据不因此改变。历史窗口正常裁剪时重新锚定仍有效的局部意图，UWB失效或时间乱序仍拒绝，不连接失效期间的虚假路线。
- `FollowSpeedCritic`把速度需求送入MPPI，而不是只在末级裁剪；`BrakingCritic`提前筛掉不可停车的当前候选。路线接回与停车积分使用共享C++矩形实现，减少障碍附近Python几何调用造成的调度停顿。[原生插件说明](../native/README.md)给出协议、等价检查和复现方式。
- `forward_speed.py`只在仿真中校准锁定ONNX模型的0.4～0.8 m/s响应；≤0.3 m/s不加死区或最低速度，0.3～0.4 m/s平滑衔接。最终请求仍≤0.8，策略内部输入可更高并单独记录；这不是Go2实机SDK补偿。
- 相机主点按像素中心 `(width-1)/2,(height-1)/2`，深度渲染关闭MSAA。地面邻域分别核对每个像素的射线深度，修正开阔地面被误当未知的问题；既有高处障碍仍不能仅靠地面可见而清除。
- 控制时刻只选时间戳不晚于该时刻、且仍在0.2 s有效期内的实测里程计，并使用该帧关联速度。ROS异步到达可能让最新里程计暂时领先`/clock`，不再将这种到达顺序当成数据过期；仅有未来帧或真正过期时仍停车。
- 平滑器在目标速度下降或反向时先取消指向错误方向的旧加速度，避免请求已减速而实际平滑输出仍加速。普通更新保留加速度和加加速度限制；取消旧加速度的投影不承诺处处满足原加加速度界。
- 临时制动时输入与原跟随路径仍有效，就保留MPPI动作并送零速度参考，底盘仍归零；条件恢复后不用重建控制器。以停车后是否仍有0.6 m已知直行出口作为候选软评分，并在实际正向跟随输出前重新核对名义停车末端，减少进入只能接入一两格、无法续行的口袋。零命令仍允许实际制动；观察用途沿用原区域及视野校验，不增加机身碰撞尺寸。前进因出口证据受限且已减速时，请求观察任务，不等15秒无进展超时。该出口检查是现有直行/转身搜索的充分条件，不声称排除了所有可能的曲线。


`local_map.py` 使用 121×121、0.10 m 分辨率的滚动地图，坐标固定在连续 `odom` 系。窗口按整格移动并保留重叠区，新增区为未知。

- 深度携带原始采集时间，使用该时刻 optical→odom TF，避免用当前姿态投影旧图像。
- NaN、无返回、过近或超距深度不清障。有效量程仿真设为 0.25～5 m，不是 D435i 保证量程。
- 平地 z=0 假设下，可见地面确认支撑区域；高度 0.06～0.80 m 的可见表面投影为障碍。多个高度截面的完整自由观测才能清除旧障碍，不能因为看见桌下地面就删除桌面。
- v2 明确启用 **静态历史模式**：滚动窗口内曾确认的自由空间保留，同时记录观测年龄。此前固定 30 s 过期会让机器狗已走过的脚边变回未知，反复切断绕行通道；静态模式消除这一人为自锁。底层仍保留可过期模式供比较。
- **从未观察的区域始终为未知，障碍不会因超时自动消失。** 0.9 s 深度健康门槛仍有效；它检查输入是否持续工作，不能证明侧后方没有新闯入的人或物。历史自由证据只适用于当前静态场景假设。
- 机身包络为以 `base_footprint` 为中心的 **长 0.70 m、宽 0.32 m 矩形**。按实际朝向检查完整多边形与闭栅格方盒的相交，包含内部、边、角和旋转中途扫过的区域；未知和窗口外接触均拒绝。移除了 0.48 m 圆及约 0.55 m 中心距离的硬通行阈值。绿格只表示至少一个离散朝向能容纳矩形，不保证当前朝向或整个转弯可执行。剩余净空仍是选宽路线的软偏好。

`local_planner.py` 在 `(x,y,朝向)` 上搜索，八个朝向相隔45°，前进边和转向边分别验证矩形平移、旋转扫掠，不能仅搜索绿色格。连续实测姿态先经完整几何校验接入离散图；窄通道暂时不能转到离散朝向时，尝试沿当前朝向在已知自由空间内前移，再接入有转向空间的格子。跟随终点仍在舒适距离区域，人的运动方向是软偏好；与人隔着已知障碍的候选不算完成跟随，改沿安全通道推进。未知视线不虚构为墙或自由空间，目标预测也不构成自由证据。

人还在走时，距离区域内加入沿人的运动方向的参考供给软偏好，期望覆盖2.4 s MPPI窗口及0.4 s搜索间隔；不为凑长度去未知区，短通道仍可用。人停在合适距离、当前包络和实际停车轨迹安全且没有已知隔墙时，保持当前位置；视线证据不完整单独回报 `FOLLOW_DISTANCE_UNOBSERVED`，不再反复催促移动。

**未看见理想跟随终点，不等于前方没有可走通道。** 当期望距离带暂不可达时，先在起点连通的已知安全格内选择能明显缩短目标间距、形成足够长移动参考的前方终点，返回 `FOLLOWING / KNOWN_CORRIDOR_PROGRESS`；随着新深度接入继续延伸。这样落后于快走目标时，不会因为地图尚未覆盖最终距离带就自动转为更慢的停转观察。目标在后方且没有已知路线，或当前安全通道不足以取得有效进展时，仍进入观察或等待；不允许把目标方向的未知当自由，也不允许盲退。

路径简化同时检查**碰撞、总代价和最差净空代价**。只检查“直线不碰障碍”会把 Dijkstra 特意选的宽绕行路线重新拉直贴到墙角，本轮后处理要求捷径不显著增加同口径代价，且不抹掉原路线的宽通道优势；原本狭窄但安全的通道仍可通行。`segment_cells` 使用完整接触格覆盖（supercover）：端点、格线两侧、擦过格角的四格都检查，窗口外接触直接拒绝。中心线代理代价使用这一完整接触格校验；实际路径和停车轨迹另作全矩形扫掠验证，避免只看中心线漏掉机身角点。

跟随区域与有效滚动进展都不可得时，才在已知连通区域内选择有潜在信息收益的观察位置。**仅观察终点额外要求 0.10 m 转向漂移余量**，路径依然使用原安全包络；不能把观察点的停转要求扩展成整条路径的重复膨胀。因此安全窄通道可以持续前进，即使它无法容纳原地观察。仅当确实需要观察且没有满足余量的观察点时，记录 `NO_ROBUST_OBSERVATION` 并等待；这项余量仍是待标定的仿真工程假设。

观察位置从 0.30 m 粗采样周围细化到 0.10 m 相邻格，另纳入距当前位置 0.5 m 内的候选。每轮最多评估 **32 个位置**及各自候选朝向：近身点最多占 8 席（最近稳健点、4 个优先点、3 个高净空点），保留最多 16 个粗网格空间代表，再用细化候选填剩余席位。分别预留份额，既减少近处视点被粗网格相位漏掉，也防止密集邻格把较远的粗空间代表挤出预算。收益射线遇到已知障碍即停止，不读取墙后的真实场景；细化不改变路径可通行图，也不清除未知区域。

路线及绕行侧偏好减少频繁换边。搜索读取地图副本，默认在唯一独立进程中执行；控制线程每 0.4 s 提交一次，丢弃超过 0.8 s 的旧结果，并用最新地图复查执行路线。

`observation_geometry.py` 统一预测与实际位置准入的几何验证：按半格间距密集覆盖前视扇区，近处射线负责遮挡，统计唯一世界格的未知收益。候选按 16 视野分批，用矩阵格 mask 去重和计算前沿重叠，仅对选中结果生成坐标集合；缓存射线模板，当前地图、连续位置和朝向仍重新计算。**机身平面扇区仍是预测占位，不能等同于左光心实际可测区域**；还需由 `CameraInfo`、采集时刻 TF、可测高度带/图像 ROI 与实际采集位姿限定相关前沿。优化不改变未知不可通行规则，当前尚未取得 RK3588 性能认证。

上述扇区对应旧对照 `cone`。当前默认 `camera` 用 `CameraInfo` 与采集时刻 optical→odom TF 提取实际光心、安装偏移、高度和倾斜，按图像内可测地面 ROI 与从光心出发的遮挡射线验证支持；候选未来倾斜仍是预测，缺标定不回退为机身扇区。它不将预测收益写成自由证据；旧 helper 的 camera 连续障碍试验没有执行观察任务，不能据其结果评定当前 camera 观察动作的效果。

## 4. 观察任务与 MPPI 执行

`ObservationSession` 将观察拆为 `MOVE → ORIENT → EVALUATE`，控制器按阶段切换：

| 阶段 | 控制器与到达判定 | 行为 |
|---|---|---|
| `MOVE` | `FollowPath` + `follow_goal` | 接近参考路径并持续核对相关新信息；途中收益已足够则直接结束信息任务，否则实际位置进入有效区域并通过停车空间等检查后才准入看向 |
| `ORIENT` | `Observe` + `observe_goal` | 以实际准入位置为锚点，前进候选约束为零，完成指定朝向；漂移离开有效区域则回到 `MOVE` |
| `EVALUATE` | 撤销跟踪动作、输出零命令 | 等待至少两帧朝向到位后的新深度与 0.4 s，再检查相关前沿的真实新证据，并复查朝向 |

观察区域在参考点 0.35 m 邻域中逐格验证净空、至少 10% 未知收益、至少 30% 原相关前沿覆盖，并保留连通分量；这不是把到达容差简单扩大为 0.35 m。实际连续位置入场时再次计算同一条件。原 0.08 m 位置容差用于参考点接近和无有效区域的失败出口，不能单独宣告到达或观察成功。

移动与看向使用标准 `FollowPath` 动作接口；评估时撤销动作并保持零命令。移动转为看向、漂移返回移动均清除旧候选；控制器切换撤销旧动作。评估期间若实际朝向超出 0.20 rad 容差，则返回 `ORIENT`。

完成信息任务的收益门槛仍为相关前沿至少 `max(3, ceil(开始时尚未知相关格数×5%))` 个新已知格。`MOVE` 先按**任务开始时刻至当前时刻的采集时间**统计，并要求任务开始后接入真实新深度帧；途中信息已足够时直接记录 `OBSERVATION_COMPLETE`，不用到参考点或再停转。否则先用“剩余未知收益”判断准入，会把已经揭示前沿造成的 `LOW_GAIN` 错当失败。`EVALUATE` 仍要求朝向到位之后的两帧新深度与 0.4 s，2 s 仍无足够相关证据则换视点。

只有原相关世界格的真实新证据才计收益，帧数增加、窗口滚动、其他方向的新格，以及旧/未来采集时间均不能完成任务。新已知可能是障碍，新增自由与可通行格另行记录。**信息任务完成不等于获得通道，也不等于移动参考点已经到达**，下一段路径继续由最新安全地图验证。`last_outcome` 记录完成阶段和证据时间边界，便于解释为何取消了一次冗余看向。

搜索结果返回时，先用最新地图与实测位置验证连接及整条剩余路径，通过后再接入；无效候选不会先创建任务或抢占有效观察。`invalidate_plan` 同时撤销观察上下文、路径和候选速度；输入失效、观察结束、路径冲突或上下文丢失后重新搜索。尚未开始的 Future 可取消，已运行的旧搜索按请求时间边界拒收；操作状态通信中断也通过统一 `halt` 入口更新当前时刻的时间屏障。`last_outcome` 跨下一观察任务保留上次终止原因和证据，供低频验收检查。

固定一次观察任务，避免评分轻微变化就不断换终点；出现可跟随通道时可以切回跟随。最近 24 条尝试保存实际停点、朝向及原完整观察区域；区域准入可能提前于参考点，去重须覆盖任务区域，不能只覆盖实际停点周围 0.20 m。

搜索与 Future 接入共同调用 `observation_attempted`：按当前分辨率的世界格精确排除原区域内、同视向差小于 0.35 rad 的候选，保留区域外及未尝试的新方向。区域不外扩；旧三项记录仍按原单点 0.20 m 半径判断，避免兼容处理变成扩大封锁。

实际转向 4 s 无明显角度进展，或单次观察任务总计超过 15 s，会记录失败并搜索其他视点。连续观察另有 **40 s 总预算**，侧向新增自由格不能无限延长墙前探索；15 s 无足够位移/可通行区域增长，或连续观察预算用尽，进入 `NO_PROGRESS` 并锁定本轮失败。地图后来变化不能自行重新启动运动，需要用户暂停后再恢复重试。执行端没有新增最低速度、死区或起步补偿。

`mppi_runtime.py` 运行已安装的 **ROS 2 Humble Nav2 MPPI 1.1.20**，启动专属 `/go2_follow_mppi` 命名空间内的 `controller_server` 与 `lifecycle_manager` 两个 C++ 子进程。MPPI 为差速速度模型，30 Hz、800 条采样轨迹、2.4 s 预测时域；参考路径通过标准 `FollowPath` 动作更新。普通跟随及观察移动阶段忽略终点朝向，观察转向阶段才要求完成指定朝向。

`FollowPath` 的路径方向代价权重为 5，在距终点 0.08 m 范围才关闭，与位置到达门槛一致；方向偏差门槛为 0.15 rad。这是优化器软代价，不是“偏角超过门槛就硬停车或抢占绕行”的规则。此前 0.30 m 的关闭范围会让尚未走完的短路线失去转向引导。`Observe` 关闭路径方向代价，使用终点朝向代价完成固定位置看向，避免两种朝向要求互相争夺。

`mppi_bridge.py` 将同一历史几何地图送入 Nav2，未知区在 MPPI 地图中同样不可穿越。MPPI 发布 `/follow_demo/mppi_cmd` **候选**速度，最终 `/cmd_vel` 只由跟随节点统一发布；暂停、输入失效、重置和过时动作不能继续执行旧速度。MPPI 命令超过 0.3 s 未更新时停车。

`heading` 保留锁定上游的航向语义：请求角速度先积分为目标航向，再通过 `clip(0.5×wrap(目标航向−实测航向), ±1)` 生成模型角速度；`velocity` 直接输入仅用于配对诊断，当前默认执行是下述 `rate`。历史原地 0.40 rad/s 配对基准中，直接模式稳态约 0.0064 rad/s、heading 约 0.3987 rad/s；后者仍有约 2.442 s 的响应建立时间和侧向漂移。全零指令重置目标航向是当前停车策略与上游保留旧航向的差异，不能宣称复制了全部上游行为。

`rate` 使用独立 `YawRateServo`，根据实测机身角速度生成前馈加 PI 的模型转向输入，不另积累航向目标。前馈增益从原地 2.4 插值至前速 0.5 m/s 时的 1.6，PI 为 `Kp=0.35、Ki=0.5`，测量低通时间常数 0.08 s，并限制模型输入 ±1、抑制饱和积分。前馈端点有锁定模型基准来源，中间插值和反馈增益仍是实验选择。独立基准已检查前速 0、0.3、0.5 m/s 下请求 ±0.4 rad/s 的正反转；原地请求 ±0.8 rad/s 未准确跟踪，不能把模型输入 ±1 理解为机身可实现 ±1 rad/s。详细数值及停车边界见 [本轮记录](../artifacts/连续跟随时钟与转向验收记录_20261004.md)。

普通跟随和绕行采用距离需求、曲率共同决定的连续速度限制，前进命令上限 **0.8 m/s**，观察上限 0.45 m/s。MPPI、最终执行和仿真接收端统一使用 `MAX_NAVIGATION_TURN=1.0 rad/s`，转向采样标准差为 0.20 rad/s；这是用户指定的指令边界，实际模型能力另行测量；当前原地请求±1.0 rad/s未准确跟踪，不能将上限理解为实际可达转速。提高追赶余量，是因为步态策略的实际运动速度可能低于输入指令；指令上限不等于已达到实测 0.5 m/s。线/角加速度与加速度变化率约束负责平滑，硬停车保护优先于舒适性。

最后同时校验待下发命令与实测速度的短时停车轨迹。请求转向可能尚未建立，也可能与残余实际转向相反；因此候选前速取请求与实际正前速的较大值，分别用**请求转速、实际转速、两者中间值**组合实际侧向速度检查停车，任一组合不安全就拒绝。全零指令也按实测运动检查，不能预测成静止点。仿真假设减速度为线性/侧向0.45 m/s²、角速度1 rad/s²。静态历史地图已按采集时刻TF补偿，保持时间取执行假设0.25 s，不再将图像年龄重复加作执行延迟；深度健康门槛仍为0.9 s。轨迹每一步之间都作完整矩形平移及旋转扫掠校验。前进受限时保留仍安全的转向，每个候选重新检查。

这项混合保护补上已经观察到的转向延迟与侧移失配，**没有构成完整的实机可达轨迹管**，不能覆盖未辨识的所有过冲或响应时延。MPPI 仍采用理想差速预测，当前制动数值也不是 Go2 实机标定参数。

目标停下且距离已合适时，先稳定0.4 s；与人方位的偏差超过0.12 rad，且整段转身的矩形扫掠已确认安全，进入 `FACING`，仅原地转向。偏差低于0.06 rad后进入 `HOLDING`；没有完整已知转身空间则保持停车。行走和绕障对齐路径，人方位不抢占绕行。界面分开显示机身朝向、人方位、路径方向以及请求/实测转速，单个UWB标签不能测量人体自身朝向。

## 5. 传感器、ROS 与物理边界

`FollowerNode` 不持有模拟器对象，只订阅深度、内参、UWB、里程计和操作状态。传感器桥、导航和 `TfReceiver` 使用独立 ROS 执行器，TF 线程只维护线程安全变换缓冲区；所有 core 状态、地图事务接入和最终命令仍由唯一控制线程修改。里程计与操作状态队列只保留最新一条，避免控制负载升高时消费积压旧状态。搜索默认使用独立spawn进程，只读取地图快照；Nav2控制器使用专属进程。其他Python回调仍在实验台进程内，不能据此声称所有故障均已隔离。

本机独立 30 s 时钟采样捕获到系统日期相对单调时钟回跳 **2.298136 s**，见 [原始采样](../artifacts/system-clock-probe-20261004.json)。此前异常栈显示两个 ROS 执行器都在 `wait_set.wait`，主回调已退出，物理和深度交付仍前进；这缩小了调度问题范围，但独立时钟采样不是旧两次空档的同事件唯一因果证明。`SensorBridge` 现显式以 `STEADY_TIME` 定时，避免周期任务受日期校时影响；`/clock` 与传感消息的 stamp 仍来自物理仿真时间，导航控制继续使用仿真时钟。

独立监视器只在回调进入间隔超过 0.6 s 时记录线程名、Python 栈、物理快照时间及阶段；恢复后才重新允许，至少间隔 1 s，最多 32 条、2 MiB。0.6 s 仅为诊断触发值，不改变 0.35 s 看门狗或 0.9 s 深度健康门槛。`scheduling_monitor` 同时记录日期/单调时间差分和最多八次跳变；闭环复测需要确认日期仍有回跳时，桥的调度是否持续，而不是只检查“本次没有回跳”。

当前默认 `steady` 另以单调时钟线程每 20 ms 唤醒三个执行器，`native` 保留原生等待作对照；ROS 定时器与消息采集时间不变。两次纯时钟 A/B 探针各 120 s、合计约 240 s，没有自然回跳，均为 `NOT_DEMONSTRATED`。新候选用 `previous_stages_ms` 分解控制耗时，`halt_counts` 和最近 32 条 `halt_events` 保存短停状态进入及输入年龄，深度提交原因 `WAIT_CAPTURE_TF`、等待计数与异常文本解释有帧但未提交的情况。它们是定位证据，不是新的安全判定。本轮五场没有捕获日期回跳，抗自然回跳验证仍为NOT_DEMONSTRATED；当前物理结果见 [本轮记录](../artifacts/本轮跟随优化与验收_20261005.md)。

深度融合也放入唯一后台线程，回调仅保留最新帧，避免深度投影占住速度接收与控制心跳。线程只写地图副本，控制线程接入时核对场景 `epoch`、原地图对象、采集时间健康门槛和是否已被新帧替代。窗口布局版本与观测内容的 `evidence_version` 分开：仅滚动窗口移动时，副本按世界坐标重对齐当前布局再提交，新增边缘仍为未知；重置、起始净空确认或其他新观测改变内容时仍拒收旧副本。拒收或计算失败不刷新深度健康时间，0.9 s 健康门槛继续有效。

CSV 使用有界队列和唯一写入线程，实时回调只非阻塞投递。慢磁盘或日志下载不会拿着界面缓存锁拖住传感器；队列满时丢日志并记录数量，不阻塞运动控制。下载导出已写入部分，正常关闭会排空已入队日志并等待写入线程退出；诊断记录排队、写入、丢弃、失败和写入耗时。

D435i 几何采用 0.050 m 名义双目基线、58° 垂直视场、424×240 灰度图。左光心深度为 **212×120、32FC1、米制理想渲染深度**，不是双目匹配输出，也不是厂家完整 D435i 仿真。未模拟主动投影、IR 材质、曝光、纹理不足、真实深度孔洞或独立 RGB 流；细杆、悬空物与反光物仍需专门验证。

虚拟 UWB 目标是无碰撞标记，从深度渲染中排除。未模拟人体遮挡、动态人体障碍或多人；真实人体不能简单从障碍地图中排除。相机中点相对机身 `[0.23, 0.025, 0.135] m`、IMU 同点同轴均为待测安装假设。IMU 为原始角速度与比力，不输出融合姿态。UWB 20 Hz、60 ms 传输延迟、测距噪声标准差 0.015 m、测角 0.003 rad，未包含真实 NLOS、多径和人体遮挡。仿真同步不能替代实机时钟、曝光和外参验证。

导航深度使用本进程的独立渲染线程，低频界面使用**唯一spawn渲染子进程**，分别持有私有 `mjData` 和渲染上下文。深度目标频率 8 Hz；界面灰度双目 2 Hz、全景图 1 Hz，JPEG编码只在界面子进程执行。左右图仍取同一冻结物理快照，低频界面不能拖慢导航深度交付；实际频率与最大渲染耗时另行记录，负载超时不补发积压旧帧。目标频率不是性能保证，效果须看本轮采集时间和实际交付频率。

TF 为 `odom → base_footprint → base_link → camera_*`；重置时 ROS 时间仍单调，用 `epoch` 隔离旧输入和动作。物理步进 2 ms、策略周期 20 ms，复用锁定 ONNX 模型与 PD 力矩，不直接移动机器人位姿；执行端有 0.35 s 墙钟命令看门狗。

## 7. 文件职责与下一阶段

| 文件 | 职责 |
|---|---|
| `controller.py` | UWB 时间对齐与目标估计，保留首版跟随核心供比较 |
| `local_map.py` | 采集时间投影、历史证据、滚动地图与完整线段接触格校验 |
| `local_planner.py` | 已知通道滚动进展、多目标图搜索、保留净空的简化与观察候选 |
| `observation.py` | 移动中信息完成、实际区域准入、漂移回退和相关新深度反馈 |
| `observation_geometry.py` | 密集视野、格 mask 批量收益、相关前沿与区域几何验证 |
| `navigation_config.py` | 搜索、控制与到达判定共享容差 |
| `navigation.py` | 异步计划管理、旧 Future 拒收、连续限速与实测残余运动停车检查 |
| `policy.py` | 锁定步态模型输入、航向外环、动作滤波和 PD 执行 |
| `yaw_rate.py` | 独立前馈加 PI 角速度执行实验及参数诊断 |
| `executor_pulse.py` | 单调时钟周期唤醒执行器，提供 native / steady 对照身份 |
| `mppi_bridge.py`、`mppi_runtime.py` | Nav2 动作/地图桥接与专属子进程生命周期 |
| `ros_nodes.py` | 传感器接口、独立 TF 接收、采集时间地图事务、阶段/短停诊断与独立 CSV 写入 |
| `scenarios.py`、`simulation.py` | 物理场景、目标路线、独立深度/界面渲染和接触统计，不向导航泄漏场景真值 |
| `static/index.html` | 人工验收与可视化 |
| `tests/render_follow_replay.py` | 将真实报告及采样生成可双击的离线验收回放，不启动服务 |
