面向**语音识别上层**和**现场操作者**的交付文档。字段级细节另见
[UPSTREAM_API.md](UPSTREAM_API.md)；本文覆盖：谁启动什么、怎么调、怎么验收、踩什么坑。

- 代码位置：`~/robot_ws/go2_follow_develop`（分支 `develop`），包 `go2_uwb_behavior`
- 行为节点常驻且默认 **IDLE**：不接到 Action 不动、不跑双目

## 2. 启动（四个终端，顺序无所谓，但要全部起来）

### T1 底盘层（提供 `/leg_odom2`、TF、`/cmd_vel` → 狗）

```bash
ros2 launch transfer lite3_bringup.launch.py
```

> ⚠️ 这条会让狗的 UDP 指令通道保持活跃，不是只读。狗**不接遥控器也能被程序驱动**。

### T2 双目相机（emitter 必须在驱动起来之前关）

```bash
~/bin/rs-emitter 0 && ros2 launch realsense2_camera rs_launch.py \
  enable_infra1:=true enable_infra2:=true \
  depth_module.infra_profile:=640,480,15 \
  depth_module.depth_profile:=640,480,15 \
  rgb_camera.color_profile:=640,480,15 \
  enable_rgbd:=true enable_sync:=true align_depth.enable:=true
```

话题必须是 `/camera/camera/infra1/image_rect_raw` 与 `infra2/image_rect_raw`（行为链默认值就是这两个）。

### T3 UWB 串口

```bash
ros2 launch uwb_aoa_pkg uwb_source.launch.py
```

### T4 行为链（本次交付的唯一新入口）

```bash
# 首次联调：接口、点云、规划、诊断全跑，但**底盘速度恒为零**
ros2 launch go2_uwb_behavior behavior_follow_roam.launch.py enable_motion:=false

# 确认无误后放开运动
ros2 launch go2_uwb_behavior behavior_follow_roam.launch.py enable_motion:=true
```

它自己会拉起 6 个节点：`uwb_behavior_controller_node`、`uwb_target_adapter_node`、
`stereo_obstacle_projector_node`、`disparity_node`、`rolling_obstacle_map_node`、
`local_velocity_planner_node`。**不要**再单独启动 `local_follow.launch.py`、
`uwb_follow_only.launch.py` 或 `local_velocity_planner.launch.py` —— 它们都会往
`/cmd_vel` 发速度，会打架。

### 首次实机建议：把就绪窗口放宽到 4 秒

默认 `readiness_timeout_sec: 2.0`。从「收到 Goal」到「障碍点云真正新鲜」要串起
投影建订阅 → 双目出视差（实测约 4 Hz）→ 投影 → 滚动地图 2 帧确认，
首帧链路可能贴近 2 秒而误报 `NOT_READY`。首次可临时覆盖：

```bash
cp ~/robot_ws/go2_follow_develop/src/go2_uwb_behavior/config/behavior_controller.yaml /tmp/behavior_first.yaml
sed -i 's/^    readiness_timeout_sec: 2.0/    readiness_timeout_sec: 4.0/' /tmp/behavior_first.yaml
ros2 launch go2_uwb_behavior behavior_follow_roam.launch.py \
  enable_motion:=true behavior_params_file:=/tmp/behavior_first.yaml
```

跑顺后把参数改回 2.0 或直接用默认配置文件。

## 3. 上层接口

### 3.1 语音意图 → 接口

| 语音 | 接口 | 生命周期 |
| --- | --- | --- |
| 「跟着我」 | Action `/go2/follow_uwb`（`FollowUwb`） | 一直跟到 cancel 或超时 |
| 「别跟了」 | 取消上面那个 Goal | 停车确认后返回 `CANCELED` |
| 「原地玩耍」 | Action `/go2/random_roam`（`RandomRoam`） | 走到一个随机目标后**自动结束** |
| 「停下」 | Service `/go2/set_behavior`，`mode=2`（STOP） | 锁存停车，**拒绝后续新任务** |
| 「解除停止」 | Service `/go2/set_behavior`，`mode=0`（IDLE） | 恢复可接收任务 |

两个 Action **全局互斥**。已有任务在跑时再发一个 → 直接 `accepted=false`，上层应先 cancel 再发。

### 3.2 「跟着我」

Goal：`float64 timeout_sec` —— `0` 表示一直跟到上层取消；显式值只接受 **5～3600 秒**。

```bash
ros2 action send_goal /go2/follow_uwb go2_uwb_behavior/action/FollowUwb \
  "{timeout_sec: 0.0}" --feedback
```

Feedback（5 Hz）：`state` = `STARTING`/`FOLLOWING`/`HOLDING`/`INPUT_PAUSED`/`STOPPING`，
另有 `distance`、`heading`、`elapsed_sec`。

Result：`code` + `message` + `elapsed_sec` + `final_distance`。

| code | 含义 | 上层该怎么办 |
| --- | --- | --- |
| `CANCELED` | 上层取消（正常结束方式） | 提示「已停止跟随」 |
| `NOT_READY` | 2 秒内 UWB/里程计/障碍/规划器没齐 | 提示「设备未就绪」，可 2 秒后重试 |
| `INPUT_TIMEOUT` | 关键输入断了且 3 秒内没恢复 | 同上，检查相机/UWB |
| `TIMEOUT` | 到达 Goal 里指定的时限 | 提示后结束 |
| `PREEMPTED_BY_MODE` | 被 STOP/IDLE 抢占 | 提示「已打断」 |
| `STOP_UNCONFIRMED` | 停不下来（里程计没确认停稳） | **按异常处理**，提示人工查看 |

> `STATUS_CANCELED` + `code=CANCELED` 是「停止跟随」的**正常终态**，不要当错误。
> 上层必须保存 Goal Handle，「别跟了」是 cancel 它，而不是发 STOP（STOP 会锁存）。

### 3.3 「原地玩耍」

Goal：`uint32 random_seed`（0=随机）、`float64 timeout_sec`（0=默认 30 秒，显式值 5～120 秒）、
`float64 min_radius`、`float64 max_radius`（都填 0 时用默认 0.5～2.0 米）。

```bash
ros2 action send_goal /go2/random_roam go2_uwb_behavior/action/RandomRoam \
  "{random_seed: 0, timeout_sec: 30.0, min_radius: 0.5, max_radius: 2.0}" --feedback
```

**半径是以「收到 Goal 那一刻的 UWB 位置」为圆心冻结的**（见 §4.3）。所以上层传的是
「狗在当前主人周围多远范围内玩」的语义，不是世界坐标。

Result 里 `center_pose`（冻结圆心）、`target_pose`（选中目标）、`reached_pose`（结束位姿）、
`owner_distance`、`min_clearance`、`code`、`message`。

**成功判定必须同时满足**：Action 状态 `STATUS_SUCCEEDED` **且** `code == SUCCESS`。
其他 code：`CANCELED`、`PREEMPTED_BY_MODE`、`NOT_READY`、`NO_VALID_GOAL`（采样不到安全点）、
`BLOCKED`（3 个目标都没走通）、`TIMEOUT`、`INPUT_TIMEOUT`、`GEOFENCE_STOP`（持续触发 6 米围栏）、
`STOP_UNCONFIRMED`。任何非成功结果**都不要**接着做跳跃/摆腿等后续动作。

### 3.4 Python 示例（已实测通过）

```python
import rclpy
from rclpy.action import ActionClient
from rclpy.node import Node

from go2_uwb_behavior.action import FollowUwb, RandomRoam
from go2_uwb_behavior.srv import SetBehavior


class UwbTaskClient(Node):
    """语音层用的最小客户端：跟着我 / 别跟了 / 原地玩耍。"""

    def __init__(self):
        super().__init__('voice_uwb_task_client')
        self._follow = ActionClient(self, FollowUwb, '/go2/follow_uwb')
        self._roam = ActionClient(self, RandomRoam, '/go2/random_roam')
        self._set_behavior = self.create_client(SetBehavior, '/go2/set_behavior')
        self._follow_handle = None

    def start_follow(self, timeout_sec=0.0):
        """跟着我：0 表示一直跟到 stop_follow()。返回是否被接受。"""
        if not self._follow.wait_for_server(timeout_sec=3.0):
            return False
        goal = FollowUwb.Goal()
        goal.timeout_sec = timeout_sec
        handle = self._spin(self._follow.send_goal_async(goal, self._on_feedback))
        self._follow_handle = handle if handle.accepted else None
        return handle.accepted

    def stop_follow(self):
        """别跟了：取消并等待节点停车确认。返回业务结果码，失败返回 None。"""
        if self._follow_handle is None:
            return None
        self._spin(self._follow_handle.cancel_goal_async())
        result = self._spin(self._follow_handle.get_result_async())
        self._follow_handle = None
        return result.result.code

    def random_roam(self, min_radius=0.5, max_radius=2.0, timeout_sec=30.0, seed=0):
        """原地玩耍：走完一个目标自动结束。返回 (状态, Result)。"""
        if not self._roam.wait_for_server(timeout_sec=3.0):
            return 'no_server', None
        goal = RandomRoam.Goal()
        goal.random_seed = seed
        goal.timeout_sec = timeout_sec
        goal.min_radius = min_radius
        goal.max_radius = max_radius
        handle = self._spin(self._roam.send_goal_async(goal, self._on_feedback))
        if not handle.accepted:
            return 'rejected', None
        # 结果要等任务真正跑完，等待上限必须比 goal 自己的超时留出余量
        result = self._spin(handle.get_result_async(), timeout_sec=timeout_sec + 15.0)
        return result.status, result.result

    def set_behavior(self, mode):
        """mode: SetBehavior.Request.STOP(2) 锁存停车 / IDLE(0) 解除。返回是否被接受。"""
        if not self._set_behavior.wait_for_service(timeout_sec=3.0):
            return False
        request = SetBehavior.Request()
        request.mode = mode
        response = self._spin(self._set_behavior.call_async(request))
        return bool(response and response.accepted)

    def _on_feedback(self, feedback):
        # 上层要显示进度时在这里取 feedback.feedback.distance / state
        pass

    def _spin(self, future, timeout_sec=15.0):
        """阻塞等待；超时直接抛错，避免把 None 当成正常结果用下去。"""
        rclpy.spin_until_future_complete(self, future, timeout_sec=timeout_sec)
        if not future.done():
            raise TimeoutError(
                '%.1f 秒内没有响应：检查 ROS_DOMAIN_ID 是否与服务端一致、行为节点是否在跑'
                % timeout_sec)
        return future.result()


def main():
    rclpy.init()
    client = UwbTaskClient()
    try:
        if client.start_follow():
            # 上层在这里挂起，直到语音说「别跟了」
            print('follow stopped with code', client.stop_follow())
        else:
            print('follow goal 未被接受')
        status, result = client.random_roam()
        print('roam status', status, 'code', getattr(result, 'code', None))
    except TimeoutError as error:
        print('调用超时：', error)
    finally:
        client.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

要点：`send_goal_async` 是异步的，示例用 `rclpy.spin_until_future_complete` 等；
真实语音层建议改成回调或独立执行器，**不要阻塞语音主循环**。

## 4. 必须知道的约束

### 4.1 `/cmd_vel` 只有行为节点能发

行为节点从启动起就以 20 Hz 持续发 `/cmd_vel`（空闲时是零）。任何第二个发布者都会打架。
`local_velocity_planner.launch.py` 与 `uwb_follow_only.launch.py` 的默认输出话题**已经被改成
`/cmd_vel`**，所以**不要单独启动它们**（`enable_motion:=true` 时尤其危险）。

### 4.2 空闲时狗交回遥控器

`lite3_twist_bridge` 的逻辑：`/cmd_vel` 非零 → 切 **Vision Mode**（程序接管）；
连续归零超过 `idle_timeout`（默认 1 秒）→ 退回 **Joystick Mode**（遥控器接管）。

后果：跟随时主人站着不动超过 1 秒，狗会退回遥控器模式；主人再走，它自动切回 Vision。
这是既有链路的行为，不是本次引入的问题。若不想看到频繁切换：
`ros2 param set /lite3_twist_bridge idle_timeout 10.0`。

### 4.3 「玩耍」的圆心是冻结的

`RandomRoam` 在 Goal 被接受时冻结当时的 UWB 位置为圆心，之后的采样半径、软返回（5 米）、
硬围栏（6 米）、以及「回来」的目标点**全部相对这个冻结圆心**，不跟主人实时移动。

后果：主人走远后再喊「玩耍」，狗结束时会回到**喊话时那个位置**，而不是主人现在的位置。
默认 30 秒的单次任务下影响有限；上层若有「狗要一直待在主人身边」的强需求，请提出来改成
「围栏跟实时位置、采样跟冻结圆心」。

### 4.4 时间预算（默认参数）

| 环节 | 数值 |
| --- | --- |
| 感知链输出 | 双目视差实测约 4 Hz（640×480，RK3588S 上占约 1.4 个核） |
| 障碍点云超时 | 0.70 s 未刷新 → 立即零速 |
| 任务启动就绪窗口 | 2.0 s（首跑建议放宽到 4 s） |
| 输入中断恢复窗口 | 3.0 s 内恢复则自动继续，否则 `INPUT_TIMEOUT` |
| 停车确认 | 里程计连续 0.3 s 低于阈值；最多等 2 s |

感知链只在 Action 活动期间计算：Goal 被接受 → 门控开；结束/取消/失败 → 门控关。
**空闲时不跑双目匹配**（实测 CPU 从 1.4 核降到 2%），但相机驱动、UWB、底盘节点是常驻的。

## 5. 首次实机验收清单（按顺序做，过了再放开运动）

**A. 空跑（`enable_motion:=false`）**

```bash
ros2 node list                       # 应有 6 个业务节点
ros2 topic info /cmd_vel --verbose   # Publisher 只应有 uwb_behavior_controller_node
ros2 topic info /stereo/disparity    # 空闲时 Subscription count: 0
ros2 topic echo --once --qos-durability transient_local --qos-reliability reliable \
  /go2_uwb_behavior/compute_enable   # 空闲应为 false
ros2 run tf2_ros tf2_echo base_footprint camera_infra1_optical_frame   # 相机 TF 链要通
```

再发一次「跟着我」，观察 `/stereo/disparity` 的订阅数应从 0 变 1，`compute_enable` 变 `true`，
取消后回到 0 / `false`。

**B. 放开运动（`enable_motion:=true`），空场地、遥控器在手**

1. 站在狗正前方约 1.5 米，「跟着我」→ 应看到 `STARTING` → `FOLLOWING`
2. 慢慢走，狗跟着；停下，狗停在 1 米附近（`HOLDING`）
3. 侧向绕障碍走一段，确认不撞
4. 「别跟了」→ 应收到 `STATUS_CANCELED` 且 `code=CANCELED`
5. 「原地玩耍」（先用 0.5～2.0 米）→ 走一个目标后自动停稳并返回 `SUCCESS`
6. 「停下」→ 立刻停车；此时再发任务应被拒绝；「解除停止」后恢复

**C. 收尾（每次必做）**

各终端 Ctrl+C；行为链的 Ctrl+C 会带走它起的 6 个节点。底盘层单独执行：

```bash
bash ~/Lite3_ROS/tools/cleanup.sh
```

> ⚠️ `cleanup.sh` **只覆盖底盘层**（jetson2motion / 桥 / action / 遥控 / rviz），
> 不含相机、UWB、行为链，所以那些必须靠各自终端的 Ctrl+C。
> 它内部用 `pkill -f`，**必须单独一行执行**，不要和 `ls`/`grep` 拼在一起。

复查：

```bash
ss -lunp | grep 43897                                  # 应无输出
ps -eo args | grep -E "[u]wb_behavior|[d]isparity_node|[s]tereo_obstacle|[v]elocity_planner|[r]olling_obstacle|[t]arget_adapter|[r]ealsense"   # 应无输出
```

若复查发现残留（launch 被强杀时可能只剩个别子进程，且父进程 `ros2 launch` 会跟着赖着不走），
按**进程名的 15 字符截断形式**精确清理：

```bash
pkill -x uwb_behavior_co    # uwb_behavior_controller_node
pkill -x uwb_target_adap    # uwb_target_adapter_node
pkill -x stereo_obstacle    # stereo_obstacle_projector_node
pkill -x disparity_node
pkill -x local_velocity_    # local_velocity_planner_node
pkill -x rolling_obstacl    # rolling_obstacle_map_node
pkill -f "ros2 launch go2_uwb_behavior"    # 上面那些的父 launch（交互式终端里安全）
```

## 6. 排障

| 现象 | 可能原因 | 怎么看 |
| --- | --- | --- |
| 任务秒回 `NOT_READY` | 相机/UWB/里程计没起来，或就绪窗口太短 | `ros2 topic hz /uwb/target_point`、`/leg_odom2`、`/local_rolling_obstacle` 是否都有 |
| 点云一直是空的 | 相机没开、emitter 没关、infra 话题名不对 | `ros2 topic hz /camera/camera/infra1/image_rect_raw` |
| 门控不打开 | 行为节点和投影节点不在同一 DDS domain | `echo $ROS_DOMAIN_ID`（`.bashrc` 按 eth0 载波自动选，插线前后开的终端会不一样，**重开终端**） |
| 狗不走但日志正常 | 底盘层没起 / 被遥控器接管 | `ros2 topic hz /cmd_vel_corrected`；`idle_timeout` 是否把它交回了 Joystick |
| 两个节点抢速度 | 多启动了旧的 follow/planner launch | `ros2 topic info /cmd_vel --verbose` |
| 诊断在哪看 | — | `/go2/behavior_diagnostics`、`/stereo/obstacle_diagnostics`、`/go2_uwb_local_follow/planner_diagnostics` |
